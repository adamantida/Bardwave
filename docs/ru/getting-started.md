# Начало работы

Bardwave — это настольное приложение, консоль звукового оформления для настольных ролевых игр. Вы загружаете свои звуки, создаёте сцены и нажимаете кнопки, чтобы их воспроизводить. Микс передаётся в браузер каждого игрока по сети в виде аудиопотока (stream), поэтому игрокам достаточно открыть ссылку. Это руководство проведёт вас от установки до первой игровой сессии. Полный справочник по конфигурации находится в [../../README.md](../../README.md).

> **Примечание:** Bardwave находится в разработке. Некоторые описанные здесь возможности (профили, HTTPS, мастер первого запуска, масштаб интерфейса) взяты из ветки `swarm/integration` и могут быть новее последнего опубликованного релиза. Пункты, не проверенные на реальном оборудовании, помечены **(не проверено)**.

<a id="what-bardwave-is"></a>

## Что такое Bardwave

Bardwave работает на компьютере ведущего игры (game master, GM). Он воспроизводит музыку, атмосферные звуки и звуковые эффекты из ваших файлов, микширует их в реальном времени в консоли и передаёт результат в браузер каждого игрока одним аудиопотоком Opus (кадры по 20 ms, около 64 kbit/s). Игрокам ничего устанавливать не нужно: они открывают ссылку и нажимают кнопку. Ваши файлы остаются на вашем компьютере; игроки слышат только микс, поэтому вы можете изменить звук или его уровень прямо посреди игровой сессии, и никому ничего не придётся загружать.

Учётных записей и облачного сервиса нет. Стандартная установка сама по себе не выполняет собственных сетевых запросов: проверка обновлений выключена по умолчанию, а загрузки звуков с YouTube происходят только тогда, когда вы пользуетесь этой возможностью.

Основные элементы:

- **звуковая библиотека** с группами и тегами;
- **сцены**: сохранённые наборы звуков с уровнями и затуханиями, а также **стингеры** (stinger, однократные звуки) и **эмиттеры** (emitter, случайные звуки через случайные интервалы);
- **панель музыки** с плейлистами;
- три **шины** (bus): music, ambience и sfx, с приглушением (ducking);
- **сетевой сервер** со ссылкой для игроков и страницей управления с телефона для ведущего.

<a id="requirements"></a>

## Требования

| Платформа | Запуск релиза | Сборка из исходного кода |
|---|---|---|
| Windows 10 или 11 | Звуковая карта. | Rust 1.85 или новее, с [rustup.rs](https://rustup.rs). |
| macOS 11 или новее | Звуковая карта. | Rust 1.85 или новее. Системные библиотеки не нужны. |
| Linux | Звуковая карта, GTK 3, ALSA и libxkbcommon. | Rust 1.85 или новее и пакеты для сборки, перечисленные ниже. |

> **Примечание:** Версия Rust указана в README. `Cargo.toml` её не фиксирует.

Если при запуске не удаётся открыть ни одно устройство вывода, Bardwave записывает предупреждение в журнал и продолжает передавать аудиопоток игрокам. Строка состояния внизу показывает, почему на компьютере не слышно звука.

Библиотеки для запуска в Linux (Debian и Ubuntu):

```bash
sudo apt install libgtk-3-0 libasound2 libxkbcommon0
```

Пакеты для сборки в Linux (Debian и Ubuntu). Рабочий процесс CI (workflow) устанавливает их вместе с тремя пакетами `libxcb-*-dev`, которые в этом руководстве не перечислены:

```bash
sudo apt install pkg-config libgtk-3-dev libasound2-dev libxkbcommon-dev libssl-dev
```

Для ссылок YouTube также нужен `ffmpeg` в Linux и macOS. См. [Добавление первых звуков](#add-your-first-sounds).

<a id="install"></a>

## Установка

### Из релиза

Релизы публикуются на [странице релизов GitHub](https://github.com/adamantida/Bardwave/releases). Выберите файл для своей системы:

| Система | Файл | Примечания |
|---|---|---|
| Windows | `Bardwave-v<version>-windows-x86_64.zip` | Портативный. Распаковывается в папку с `Bardwave.exe`, `config.toml` с комментариями, `README.md`, `README.txt` и `LICENSE`. |
| Windows | `Bardwave-v<version>-windows-x86_64-setup.exe` | Установщик. Устанавливает в Program Files и может добавить правило брандмауэра для TCP-порта 8080. |
| Windows | `Bardwave-v<version>-windows-x86_64.exe` | Сама программа, без `config.toml` рядом с ней. |
| macOS | `Bardwave-v<version>-macos-universal.dmg` | Неподписанный, если только релиз не был подписан. |
| Linux | `Bardwave-v<version>-linux-x86_64.tar.gz` | Распакуйте, затем запустите `bardwave`. |
| Linux | `Bardwave-v<version>-linux-x86_64.AppImage` | **(не проверено)** |
| Linux | `bardwave_<version>-1_amd64.deb` | **(не проверено)** |
| все | `SHA256SUMS` | Контрольные суммы файлов релиза. |

**Windows, портативный архив:**

1. Распакуйте архив в папку, в которую можно записывать, например `Documents\Bardwave`. Не используйте `Program Files`.
2. Запустите `Bardwave.exe`. `config.toml` рядом с ним хранит ваши данные в этой папке.

**Windows, установщик:**

1. Запустите файл `-setup.exe`. Он запрашивает права администратора.
2. Оставьте флажок **Allow Bardwave through Windows Firewall (inbound TCP 8080, private and public networks) so players can connect** установленным, если игроки будут подключаться. **(не проверено)**
3. Установщик добавляет запись в меню «Пуск» и необязательный ярлык на рабочем столе. Он не устанавливает `config.toml`, поэтому ваши данные сохраняются в `%APPDATA%\Bardwave`. Удаление программы никогда не удаляет ваши данные.

**macOS:**

1. Откройте `.dmg` и перетащите **Bardwave** в **Applications**.
2. Не дважды щёлкайте по приложению при первом запуске. Щёлкните правой кнопкой мыши (Control-click) по **Bardwave**, затем выберите **Open**, затем снова **Open**.
3. Если macOS всё равно не разрешает запуск, откройте приложение один раз, затем перейдите в **System Settings > Privacy & Security** и выберите **Open Anyway**. **(не проверено)**
4. При первом запуске macOS может спросить, разрешено ли Bardwave находить устройства в локальной сети (LAN). Разрешите это, иначе игроки из локальной сети не смогут подключиться. **(не проверено)**

**Linux, архив tar.gz:**

```bash
tar -xzf Bardwave-v<version>-linux-x86_64.tar.gz
cd Bardwave-v<version>-linux-x86_64
./bardwave
```

**Linux, `.deb`:** `sudo apt install ./bardwave_<version>-1_amd64.deb`, затем запустите **Bardwave** из меню или выполните `bardwave`. **(не проверено)**

### Сборка из исходного кода

Клонируйте репозиторий и запустите его в режиме release:

```bash
git clone https://github.com/adamantida/Bardwave.git
cd Bardwave
cargo run --release
```

В Windows вместо этого можно использовать `build.bat`. Без аргумента он собирает отладочную сборку; `release` собирает release-сборку, а `test` запускает все тесты:

```bat
build.bat release
build.bat test
```

Исполняемый файл — `target\release\soundshared.exe` в Windows и `target/release/soundshared` в остальных системах. Его можно переименовать в `Bardwave.exe` или `bardwave`.

> **Примечание:** Исполняемый файл, запущенный из `target/release`, хранит свои данные рядом с собой, внутри `target/`. Команда `cargo clean` удаляет эти данные. См. [Где хранятся данные](#where-the-data-lives).

<a id="first-launch"></a>

## Первый запуск

Окно консоли открывается размером 1280 × 800 points в тёмной вещательной раскладке: верхняя панель, звуковая библиотека слева, сетевая панель справа, панель музыки и строка состояния внизу. Окно нельзя сделать меньше 960 × 640 points.

При чистой установке с пустой библиотекой мастер первого запуска открывается карточкой в центре окна. Он не блокирует консоль и уступает место, пока открыт диалог. У него три страницы:

| Заголовок страницы | Кнопки на странице |
|---|---|
| Add your sounds | **Add sound**, **Add folder**, **YouTube**. |
| Build a scene | **Save current mix as scene**. Кнопка становится активной, когда в библиотеке есть звуки. |
| Share with players | **Start server** (**Retry server** после ошибки). Когда сервер запущен: ссылка для игроков с кнопкой **Copy** и **Show QR code**. |

Каждая страница сама отмечается, когда состояние приложения ей соответствует: в библиотеке есть звуки, существует сцена, сервер запущен.

- **Next** и **Back** переключают страницы. На последней странице вместо **Next** есть кнопка **Done**.
- **Done** закрывает карточку и не даёт мастеру открываться при следующих запусках.
- **Skip** закрывает карточку. Если хотите, чтобы мастер не появлялся при следующем запуске, сначала установите флажок **Don't show again**. Открыть его снова можно в любой момент через **Help > Getting started**.

> **Примечание:** Мастер открывается только при пустой библиотеке и если он не был окончательно закрыт. Если в конфигурации уже есть библиотека, он сразу помечается как выполненный и не открывается.

<a id="add-your-first-sounds"></a>

## Добавление первых звуков

Импорт папки читает такие аудиоформаты: `wav`, `flac`, `mp3`, `ogg`, `m4a` и `aac`. Файлы длиннее 60 секунд (`stream_threshold_secs` в `config.toml`) декодируются на лету, а не хранятся в памяти.

> **Примечание:** В окне выбора файлов, которое открывается кнопкой **Add Sound**, есть фильтр «Audio Files», показывающий `mp3`, `wav`, `ogg`, `flac` и `opus`. Выбор файлов `m4a` или `aac` таким способом и воспроизведение файлов `opus` — **(не проверено)**. Импорт папки принимает `m4a` и `aac`.

1. Нажмите **Add Sound** на панели **Sound Library**. Выберите один или несколько файлов. Или нажмите **Add folder** в мастере или **Folder…** на панели инструментов библиотеки, чтобы просканировать всю папку вместе с её подпапками. Bardwave сохраняет путь к каждому файлу и не копирует его.
2. Назначьте звукам группы или теги. Список групп **Groups** слева от списка звуков показывает **All Sounds**, **Ungrouped** и ваши группы в разделе **Categories**. Кнопка **+** в этом списке создаёт группу. Нажмите на плашку группы в строке звука (подсказка: **Change group**), чтобы переместить звук, и нажмите на текст тегов (подсказка: **Edit tags**), чтобы изменить теги. Для фильтрации используйте поле поиска (**Search name or tag…**).
3. Щёлкните правой кнопкой мыши по короткому звуку и выберите **Use As Stinger**. Стингер — однократный удар, например раскат грома, который звучит поверх сцены и получает пэд на панели **Scenes**. **Remove Stinger Flag** отменяет это действие.
4. Настройте зацикленные звуки, например дождь, на повтор переключателем зацикливания в строке (подсказка: **Repeat: on** или **Repeat: off**).

Каждая строка также содержит кнопку наушников, которая воспроизводит звук только на этом компьютере, ползунок громкости и **✕**, чтобы убрать звук из библиотеки.

Если файл перемещён или удалён, в строке появляется **File not found**. Используйте **Locate…**, чтобы заново указать файл, или **Recheck**, чтобы проверить ещё раз.

### Звуки с YouTube

1. Нажмите **YouTube** рядом с **Add Sound**.
2. Вставьте ссылку на видео или музыку в поле **Video or music link** и нажмите **Add**.
3. Дождитесь загрузки. Загружается только звук, один раз. Он конвертируется в MP3, сохраняется в `bardwave-library/` в каталоге данных и затем воспроизводится так же, как любой локальный звук. Закрытие диалога не останавливает идущую загрузку.

> **Предупреждение:** Для первой загрузки нужны `yt-dlp` и `ffmpeg`. В Windows Bardwave загружает оба в `tools/` (около 24 MB и около 230 MB). В Linux и macOS `yt-dlp` загружается автоматически, но `ffmpeg` нужно установить самостоятельно:
>
> ```bash
> sudo apt install ffmpeg    # Debian or Ubuntu
> brew install ffmpeg        # macOS, Homebrew
> ```
>
> Диалог сообщает `ffmpeg not found on this system`, если его нет. Копия `yt-dlp` или `ffmpeg` рядом с программой или в `PATH` используется раньше любой загруженной.

<a id="build-a-scene"></a>

## Создание сцены

Сцена — это сохранённый набор звуков с их уровнями. Сцены отображаются на панели **Scenes**, которая расположена внутри панели библиотеки над списком звуков.

1. Запустите несколько звуков вручную. Настройте их уровни ползунками.
2. Нажмите **Save Mix As Scene**. Кнопка активна, только пока что-то играет. В узкой раскладке её надпись сокращается до **Save Mix** или заменяется значком. Мастер вызывает то же действие под названием **Save current mix as scene**.
3. Назовите сцену в поле **Scene name**. Позже нажмите её кнопку на панели, чтобы переключиться на неё. Переход выполняется с плавным изменением громкости.
4. Используйте **Stop Scene**, чтобы выполнить затухание активной сцены. **Fade Out** выполняет затухание всего, что играет, за время перехода.

Сцены также могут содержать стингеры, зацикленные пэды и эмиттеры. Эмиттер воспроизводит случайный звук через случайные интервалы. Эмиттеры и плейлист музыки сцены настраиваются в редакторе **Emitters & music** этой сцены.

<a id="start-the-server"></a>

## Запуск сервера

Сервер передаёт микс игрокам. Запустите его до начала игровой сессии.

1. Откройте панель **Network Server** (заголовок **02 / Network**) справа.
2. Нажмите **Start Server**. Заголовок меняется на **Live**, когда сервер работает.
3. **Listen URL** показывает адрес. Нажмите **Copy Link**, чтобы скопировать ссылку для игроков.

Порт по умолчанию — `8080`. Панель показывает такие адреса:

| Адрес | Кто использует |
|---|---|
| `http://192.168.x.x:8080` | Игроки в той же сети. |
| `http://127.0.0.1:8080` | Вы, чтобы проверить страницу слушателя на этом компьютере. Панель показывает его в строке **Local**. |
| `http://<global-ip>:8080` | Игроки из интернета. Показывается в строке **Internet**, когда роутер пробрасывает порт. |

Чтобы остановить сервер, нажмите **Stop Server**.

Если сервер не запускается, панель показывает **Error** и текст сообщения, а верхняя панель — **Server failed — see panel**. Прочитайте сообщение, затем нажмите **Retry Server**.

### Автоматический проброс порта (UPnP)

При запуске сервера Bardwave просит роутер пробросить порт через UPnP. Запись о пробросе порта удаляется при остановке сервера. Чтобы выключить эту функцию, задайте `upnp = false` в `config.toml`. Строка **Internet** в этом случае скрыта.

В строке **Internet** показывается результат. Распространённые сообщения:

- **Internet: no UPnP router**: включите UPnP на роутере или пробросьте порт вручную.
- **Internet: blocked by a second NAT**: внешний адрес роутера приватный. Пробросьте порт на вышестоящем устройстве или попросите провайдера выдать публичный адрес.
- **VPN active**: VPN на этом компьютере направляет весь трафик через себя. Выключите его для игроков из интернета.

В Windows панель также может показывать **Firewall: port 8080 not opened**. Разрешите Bardwave работать и в публичных сетях или запустите программу один раз от имени администратора.

<a id="give-players-the-link"></a>

## Передача ссылки игрокам

Ссылка для игроков имеет такой вид:

```text
http://<address>:8080/?k=<access key>
```

Если вы включите HTTPS, ссылка начинается с `https://`. См. [HTTPS (защищённое соединение)](./https.md).

1. Отправьте ссылку каждому игроку с помощью **Copy Link**.
2. Игроки открывают её в любом браузере и нажимают **Establish Link**.

Ссылка заканчивается на `?k=<access key>`. Без ключа никто не сможет слушать, даже если порт открыт для интернета.

> **Предупреждение:** Нажимайте кнопку обновления рядом с **ACCESS KEY**, только если хотите отозвать ссылку. Новый ключ сразу останавливает старую ссылку и отключает всех, кто ею пользовался. После этого отправьте новую ссылку снова.

### Панель ведущего

**GM panel link** открывает удобную для телефона страницу управления по адресу `/control`. У неё собственный ключ, и ссылка для игроков её никогда не открывает. Панель показывает ссылку в замаскированном виде. Нажмите на неё, чтобы скопировать полную ссылку, или используйте **Show QR** для сканирования камерой. **New key** заменяет ключ (сначала запрашивает подтверждение).

> **Предупреждение:** Удалённое управление включено по умолчанию. Любой, у кого есть ссылка с `?g=`, может нажимать кнопки ведущего. Держите эту ссылку в тайне. Чтобы разрешить страницу управления только на этом компьютере, задайте `gm_token = ""` в `config.toml`. Тогда панель показывает **Remote panel is off: it opens on this computer only** и кнопку **Create GM key**, чтобы снова включить удалённый доступ.

<a id="headless-mode"></a>

## Режим без окна

Режим без окна (headless) запускает сервер без окна консоли. Используйте его на запасном компьютере рядом с роутером или для игровой сессии, которой вы управляете с телефона.

Для готового релиза выполните в терминале:

```bash
Bardwave.exe --server-only    # Windows
./bardwave --server-only      # Linux
```

Из исходного кода:

```bash
cargo run --release -- --server-only
```

Режим без окна:

- загружает библиотеку, сохранённую в `config.toml`;
- сразу запускает сервер для слушателей;
- записывает в журнал ссылку для игроков и ссылки управления.

В журнале появляются такие строки:

- `Listener server available at …` выводит ссылку для игроков.
- `Control page (this PC only): …/control` выводит страницу управления для этого компьютера.
- `Remote control: …/control?g=<gm_token from config.toml>` выводит ссылку на удалённую панель. Строка записывается в журнал только при включённом удалённом управлении.

На том же компьютере `http://127.0.0.1:8080/control` открывается без ключа. С другого устройства используйте `http://<address>:8080/control?g=<gm_token>`. Токен находится в `config.toml` в разделе `[server]`.

Нажмите **Ctrl+C**, чтобы остановить сервер. В Windows, если вы запускаете его из Проводника или ярлыка, он открывает собственное окно консоли для журнала, и остановить сервер можно, закрыв это окно.

`--profile` и настройка HTTPS тоже работают в режиме без окна.

> **Примечание:** В режиме без окна не работают горячие клавиши и таймеры сессии. Чтобы изменить библиотеку, отредактируйте её в консоли и затем перезапустите сервер.

### Профили

У каждой кампании может быть собственная конфигурация и библиотека. Запускайте нужный профиль с помощью `--profile`, например `cargo run --release -- --profile "Curse of Strahd"` (также работает `--profile=<name>`, а `--profile default` — профиль по умолчанию). Имена могут содержать буквы, цифры, пробелы, `-` и `_`, длиной до 32 символов. Меню **Profile** на верхней панели переключает профили. При переключении ваша работа сохраняется, и Bardwave перезапускается с другим профилем.

<a id="a-tour-of-the-console"></a>

## Обзор консоли

### Верхняя панель

| Элемент | Что делает |
|---|---|
| Надпись-логотип и **Broadcast Console** | Фирменное название и подпись. В узком окне подпись скрывается. |
| Ползунок **Master** и процент | Общая громкость. Подсказка: **Master volume**. |
| **STOP ALL** | Немедленно останавливает всё: звуки, активную сцену, музыку и предпрослушивание (preview) в наушниках. Подсказка: **Stop all sounds immediately (panic)**. Когда ничего не играет, кнопка выглядит затемнённой, но продолжает работать. |
| **REC** | Записывает микс, который слышат игроки, в файл WAV. Во время записи показывает **Stop rec**. Кнопка папки рядом выбирает папку записей. |
| **Profile** | Название текущего профиля. Его меню показывает недавние профили, а также **New profile…**, **Manage profiles…** и **Open data folder**. |
| **Help** | Содержит **Getting started**, который снова открывает мастер. |
| Состояние | **Live**, **Starting**, **Error** или **Off Air**, со второй строкой, например **Server running** или **Server failed — see panel**. |

Кнопки на экране написаны заглавными буквами, но надписи в этом руководстве совпадают с кодом. В узком окне панель сокращает надписи и убирает некоторые части.

### Звуковая библиотека

Левая панель **01 / Library** (с заголовком **Sound Library**) показывает звуки и группы. **Add Sound** добавляет файлы, **YouTube** добавляет ссылку, **Folder…** сканирует папку, а **Export…** и **Import…** работают с комплектами `.zip`. Под списком закреплённая строка **Master Output** содержит ползунок громкости и кнопку **Mute** / **Unmute**.

### Панель сцен

Панель **Scenes** находится над списком звуков. Она содержит кнопки сцен, пэды **Stingers**, **Stop Scene**, **Fade Out** и время перехода **Transition** (**Auto** использует собственные затухания каждой сцены). Используйте **New**, чтобы создать пустую сцену, **Save Mix As Scene**, чтобы сохранить текущий микс, и **Show** или **Hide**, чтобы свернуть панель.

### Панель музыки

Панель музыки находится над строкой состояния.

- Кнопки **Previous track**, **Play** / **Pause** / **Resume**, **Stop** и **Next track** управляют текущим плейлистом.
- Строка «сейчас играет» показывает трек и его положение, а также полосу перемотки. В состоянии простоя выводится **No music playing**.
- **Shuffle** и **Repeat** (off, all или one) задают режим воспроизведения.
- **Music…** открывает диалог **Music & scenes** с вкладками **Playlists** и **Scenes**. Плейлисты воспроизводятся как фоновая музыка. Сцена может запускать плейлист, а вкладка **Scenes** ведёт к редактору **Emitters & music** каждой сцены.

### Сетевая панель

Правая панель **02 / Network** (с заголовком **Network Server**) содержит сверху вниз:

- состояние сервера с кнопками **Start Server** / **Stop Server** и **Copy Link**;
- **Listen URL**, строки **Local** и **Internet** и сетевые предупреждения;
- строку **ACCESS KEY** с кнопкой обновления и **GM panel link**;
- количество **Listeners** и его пиковое значение;
- раздел **Mix**: фейдеры шин, **Duck**, **Hotkeys**, **Timers**, настройки приглушения, нормализацию громкости (loudness normalization) и **Interface** (ползунок масштаба);
- **Audio output** для звуковой карты и отдельного устройства для наушников;
- **Updates** с кнопкой **Check for updates**;
- **Secure connection (HTTPS)**;
- **Configuration**: **Port** и **Bind Address**, которые можно редактировать только при остановленном сервере.

Строка состояния внизу показывает версию, локальный вывод, формат и счётчики библиотеки, а также ссылку **Update available**, если проверка обновлений нашла новую версию.

<a id="interface-scale"></a>

## Масштаб интерфейса

Масштаб позволяет сделать консоль крупнее или мельче.

1. Откройте панель **Network** и прокрутите до конца раздела **Mix**.
2. Найдите **Interface**, затем ползунок **Scale**.
3. Перетащите ползунок, чтобы задать масштаб. Диапазон — от 80 % до 160 % с шагом 5 %.
4. Нажмите **Reset**, чтобы вернуться к 100 %. При 100 % кнопка неактивна.

Масштаб применяется, когда вы отпускаете ползунок, и запоминается в `config.toml`. Масштабирование с клавиатуры (Ctrl с + или -) отключено, поэтому ползунок — единственный элемент управления.

Параметр конфигурации — `[gui] ui_scale`. Он записывается, только если отличается от 1.0:

```toml
[gui]
ui_scale = 1.3   # 1.0 = 100 %; allowed range 0.8 to 1.6
```

Значение, изменённое вручную и выходящее за диапазон, ограничивается его границами. Некорректное значение возвращается к 1.0.

Окно сохраняет минимальный размер 960 × 640 points и увеличивается, если больший масштаб сделает его слишком маленьким.

<a id="where-the-data-lives"></a>

## Где хранятся данные

Bardwave хранит `config.toml`, библиотеку, записи и загруженные инструменты в **каталоге данных**. Расположение выбирается один раз при запуске. Используйте первое подходящее правило ниже:

| Ситуация | Каталог данных |
|---|---|
| `config.toml` уже лежит рядом с программой (в Windows — только если эта папка доступна для записи) или там есть файл `portable.flag` | Папка программы. |
| Папка программы доступна для записи и не находится внутри macOS `.app` | Папка программы. |
| macOS `.app` | `~/Library/Application Support/Bardwave` |
| Windows, например установлен в Program Files | `%APPDATA%\Bardwave` |
| Linux | `$XDG_DATA_HOME/bardwave`, или `~/.local/share/bardwave` |

Если выбранную системную папку не удаётся создать или отсутствуют переменные домашнего каталога, Bardwave использует папку программы.

| Элемент | Расположение |
|---|---|
| `config.toml`, загруженные звуки `bardwave-library/`, файлы HTTPS `tls/` | Каталог данных активного профиля. |
| Записи `recordings/` | Каталог данных активного профиля, если не задан `recordings_dir`. |
| Журнал `bardwave.log` (только при `file_logging = true`), загруженные инструменты `tools/`, недавние профили `recent.toml` | Общий корневой каталог данных. |

Для именованного профиля конфигурация и библиотека находятся в `profiles/<name>/` внутри каталога данных. Профиль по умолчанию использует сам каталог данных.

### Портативный режим и сброс

Чтобы хранить все данные рядом с программой, создайте пустой файл `portable.flag` в папке программы. Windows-архив делает то же самое с помощью `config.toml`, который в нём есть. Внутри macOS `.app` папка программы — это `Contents/MacOS` **(не проверено)**; изменение приложения может нарушить его подпись.

Чтобы сбросить Bardwave, удалите каталог данных. Вместе с ним удалятся и ваши другие профили, которые в нём хранятся. Удаление программы никогда не удаляет каталог данных.

<a id="common-problems"></a>

## Частые проблемы

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Игроки не могут подключиться по локальной сети | Брандмауэр блокирует порт. | Разрешите Bardwave в брандмауэре для частных и публичных сетей. В Linux откройте TCP-порт 8080. В macOS разрешите для Bardwave **Local Network** в **System Settings > Privacy & Security**. **(не проверено)** |
| Строка **Internet** отсутствует | `upnp = false` в `config.toml`. | Задайте `upnp = true` или пробросьте порт вручную. |
| **Internet: no UPnP router** | UPnP выключен на роутере или роутер не ответил. | Включите UPnP или пробросьте порт вручную. |
| **Internet: blocked by a second NAT** | Внешний адрес роутера приватный. | Пробросьте порт на вышестоящем устройстве или получите публичный адрес. |
| **VPN active** | VPN направляет трафик этого компьютера. | Выключите VPN для игроков из интернета. |
| **Firewall: port 8080 not opened** (Windows) | Bardwave не смог добавить своё правило брандмауэра. | Разрешите Bardwave работу в публичных сетях или запустите программу один раз от имени администратора. |
| Консоль не запускается и показывает `config.toml could not be read` | В `config.toml` некорректный TOML. | Исправьте файл или переместите его в другое место, чтобы запустить программу с настройками по умолчанию. |
| Горячие клавиши не срабатывают, когда активно другое окно | Глобальные горячие клавиши выключены. | Установите флажок глобальных горячих клавиш в диалоге **Hotkeys** или задайте `global_hotkeys = true` в `[gui]`. В macOS и Linux **(не проверено)**; в Linux они работают только на X11. |
| YouTube сообщает `ffmpeg not found on this system` | `ffmpeg` отсутствует в Linux или macOS. | Установите `ffmpeg` через менеджер пакетов. |
| У звука отображается **File not found** | Файл перемещён. | Нажмите **Locate…** или **Recheck**. |
| Панель показывает **Error** | Сервер не смог запуститься, например порт уже занят. | Прочитайте сообщение на панели, измените порт в разделе **Configuration** при остановленном сервере, затем нажмите **Retry Server**. |

<a id="not-verified-on-real-hardware"></a>

## Не проверено на реальном оборудовании

Следующие пункты реализованы и покрыты тестами или сборками CI. Их не запускали на реальных машинах:

- Установщик Windows и пакеты Linux (AppImage, `.deb`).
- macOS `.app`, `.dmg`, универсальный бинарный файл, запрос «Local Network» и подпись.
- Глобальные горячие клавиши в macOS, а также в Windows и Linux (X11).
- MIDI. По умолчанию выключен, не подключён к консоли и требует `--features midi`.
- Названия аудиоустройств в Windows (WASAPI) и Linux (ALSA или JACK).
- UPnP с реальными роутерами.
- Страница слушателя в iOS Safari и Android Chrome, включая установку на домашний экран.
- HTTPS с самоподписанным сертификатом на реальном телефоне.
- Выбор каталога данных в каждой ОС, а также профили, мастер первого запуска и масштаб интерфейса в Windows и Linux.
