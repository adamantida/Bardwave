Это руководство для тех, кто собирает, тестирует или меняет Bardwave. Оно описывает код таким, какой он есть в репозитории. О том, что приложение делает для игроков и ведущего (game master, GM), читайте корневой `README.md`. Если это руководство и код расходятся, верен код.

Пункты, помеченные **(не проверено)**, не запускались на указанном оборудовании или в указанной ОС.

<a id="architecture"></a>
## Архитектура

Консоль (egui) и сервер в режиме без окна (headless), запущенный с `--server-only`, используют одно управляющее ядро, `Director`. Действия консоли, горячие клавиши, таймеры и страница управления с телефона сводятся к операциям `Director`, поэтому сцена работает одинаково везде.

```text
egui console ──AudioCommand──┐
hotkeys / timers ────────────┴─▶ Director ──Playback──▶ AudioEngine ──▶ cpal (speakers)
/control: ControlAction ─▶ Board (headless) or GmBridge (console) ─▶ Director
                                                    │ MixedOutput
                                                    ▼
                                  AudioProcessor ─▶ AudioBroadcaster (Opus)
                                                    │
                                       axum HTTP + WebSocket (/ws/audio)
```

- `Director` (`src/audio/director*.rs`) владеет сценами, эмиттерами (источниками случайных звуков), плейлистами, приглушением (ducking) и панорамой (pan). У него нет собственного потока, и он не владеет движком: вызывающий код передаёт движок как `&impl Playback`. Работа, привязанная ко времени (отложенный запуск сцен, эмиттеры, переходы между треками плейлистов, хвосты кроссфейда (crossfade), результаты измерения громкости), выполняется в `Director::tick`, а `Director::next_deadline` сообщает владельцу, когда пора проснуться.
- `Playback` — это узкий интерфейс движка. `AudioEngine` его реализует, а `MockPlayback` (в `director.rs`) реализует его для тестов.
- `AudioEngine` (`engine.rs`) хранит каталог звуков, открывает вывод cpal и запускает предпрослушивания (preview). Микшер (`mixer.rs`) работает по модели pull: часами служит колбэк устройства. Если открыть устройство вывода не удаётся, `main.rs` переключается на цикл микширования в режиме без окна, который смешивает звук каждые 10 ms, поэтому слушатели всё равно получают аудиопоток (stream). Строка состояния при этом показывает, что локальный вывод выключен или не работает.
- `AudioProcessor` (небольшая структура в `main.rs`) читает буферы `MixedOutput` из движка и передаёт их модулю трансляции (broadcaster).
- Модуль трансляции (`network/broadcast.rs`) пересобирает микс в целые кадры по 20 ms, кодирует их в Opus и рассылает сессиям `/ws/audio`. Сервер (`network/server.rs`) — это маршрутизатор axum: одна и та же `build_router` отдаёт страницу слушателя, `/api/status` и `/ws/audio`, а `build_router_with_control` добавляет маршруты панели ведущего. Панель подключается в обоих режимах, и её маршруты доступны только пока сервер запущен.

Путь сигнала (из `mixer.rs`):

```text
source -> track gain (fade) -> pan -> bus gain (volume x duck) -> sum -> master -> limiter
       -> [broadcast copy] -> + local-only tracks (headphone previews) -> local limiter -> device
```

Треки только для локального вывода (local-only) формируются после того, как публикуется копия для трансляции, поэтому слушатели их никогда не слышат. Предпрослушивания используют шину (bus) с фиксированным усилением, которой не касаются ни фейдер, ни приглушение; когда выбрано второе устройство, его колбэк выводит одни только предпрослушивания.

Порядок запуска в `main.rs`: разбор `--profile`, выбор каталога данных, загрузка `config.toml` (ошибка разбора останавливает запуск на этом шаге), настройка журналирования, генерация недостающих ключей, создание движка в главном потоке, запуск потока сервера, потока AudioProcessor и потока подсчёта слушателей, затем запуск консоли (`run_gui`) или цикла без окна. При выходе он просит поток сервера остановиться (ждёт до 5 s) и останавливает движок. Переключение профиля, начатое из консоли, запускается после того, как старый процесс освободил свой порт и устройство.

<a id="threading-model-and-audio-callback-rules"></a>
## Модель потоков и правила аудио-колбэка

| Поток выполнения или задача | Владеет или делает |
|----------------|--------------|
| Главный поток | `AudioEngine` (его аудиопоток cpal — `!Send`), вызовы `Director`, `tick`; окно консоли eframe или цикл без окна (`--server-only`) |
| Колбэк устройства cpal | проход микшера; главные часы |
| Цикл микширования без окна (`mixer.rs`) | то же микширование, с темпом по дедлайнам, только пока нет устройства вывода |
| Поток `AudioProcessor` (`main.rs`) | передаёт смикшированные буферы модулю трансляции; при заполненном канале кадр отбрасывается |
| `bardwave-stream` | декодирует длинные файлы в кольцевой буфер `rtrb` |
| `bardwave-timeline`, `emitters` | таймеры и случайные или периодические звуки |
| Поток сервера | собственная однопоточная среда tokio: сервер axum, модуль трансляции, сессии WebSocket, задача UPnP; правило брандмауэра `netsh` в Windows передаётся в `spawn_blocking` |
| Короткоживущие рабочие потоки | сканирование папок (`library-scan`), диалоги, задания `decoder` и `youtube-download`, `audio-device-scan`, измерение громкости (`normalize-measure`, `loudness-analyze`), запись (`recorder`, `recorder-tee`), `update-check`, `hotkey-forwarder` |

Правила (из `Agent.md`, разделы 2.1 и 4.1; это правила для ревью, инструменты их не проверяют):

- Никогда не блокируйте поток отрисовки. Ввод-вывод файлов, вызовы `stat` и диалоги выполняются в рабочем потоке, который отвечает через канал, вычитываемый раз в кадр.
- В аудио-колбэке только микшируйте. Никаких блокировок на пути потокового чтения, никаких выделений памяти, никакого ввода-вывода. Публикация копии для трансляции использует `try_send` на ограниченном канале.
- Декодируйте и измеряйте громкость вне колбэка.
- Используйте движок только в том потоке, который его создал. Из других потоков обращайтесь к нему через команду.

> **Предупреждение:** Не вызывайте `AudioEngine` из потока сервера. Поставьте в очередь `ControlCommand`, и пусть главный поток его выполнит, как это делает панель ведущего.

> **Примечание:** `AppState` всё ещё хранит несколько общих значений `Arc<Mutex<…>>` (число слушателей, состояние UPnP, сетевые заметки, действующий `Config`). Это небольшие зеркала состояния, которые записывает поток сервера. Не добавляйте новое общее изменяемое состояние; добавляйте команду.

<a id="typed-command-channels"></a>
## Типизированные командные каналы

| Канал | Тип | Ёмкость | Направление |
|---------|------|----------|-----------|
| аудиокоманды | `AudioCommand` (crossbeam) | ограниченный, 32 | из GUI в движок и Director (вычитываются `process_audio_commands` раз в кадр) |
| серверные команды | `ServerCommand` (crossbeam) | ограниченный, 32 | из GUI в поток сервера; поток опрашивает канал каждые 50 ms и передаёт команду в `mpsc` tokio ёмкостью 32 |
| команды управления | `ControlCommand` (crossbeam) | неограниченный | из обработчиков HTTP в главный поток |
| выход микшера | `MixedOutput` (crossbeam) | ограниченный, 64 (`MixerConfig::channel_capacity`) | из микшера в `AudioProcessor`; `try_send`, никогда не ждёт |
| вход модуля трансляции | `AudioFrame` (tokio `mpsc`) | 500 (`engine_channel_capacity`) | из `AudioProcessor` в модуль трансляции; `try_send`, при заполненном канале кадр отбрасывается |
| очередь отправки WebSocket | tokio `mpsc` | 100 | из модуля трансляции в одну сессию; при заполненной очереди кадр отбрасывается для этого клиента, а соединение остаётся |
| Состояние Director | tokio `watch` для `DirectorState` | последнее значение | из Director читателям |
| Сейчас играет | tokio `watch` для `NowPlaying` (`NowPlayingFeed`) | последнее значение | из консоли или `Board` в режиме без окна в модуль трансляции |
| Ответы | crossbeam `bounded(1)` для `AudioCommand` и `ServerCommand`; tokio `oneshot` для `ControlCommand` | 1 | один ответ на команду |

<a id="wire-protocol"></a>
## Протокол обмена

### Аудиопоток слушателя: `/ws/audio?k=<key>`

Если ключ отсутствует или неверен, до переключения протокола (upgrade) возвращается HTTP 401 с телом JSON (`access_token = ""` означает, что принимается любой ключ). `/api/status?k=<key>` защищён так же.

Каждый аудиокадр — одно двоичное сообщение с 8-байтовым заголовком:

| Смещение | Размер | Поле |
|--------|-------|------|
| 0 | 4 байта | `seq_no`, u32 little-endian, +1 на каждый кадр (64-битный счётчик обрезается до 32 бит) |
| 4 | 4 байта | `server_ms`, u32 little-endian, ms с момента запуска модуля трансляции |
| 8 | переменный | один пакет Opus |

Аудиопоток: 48 kHz, стерео, 960 отсчётов на канал (20 ms), Opus с битрейтом 64 kbit/s VBR. Блоки любого размера, которые отдаёт устройство, пересобираются в целые кадры. После паузы длиннее 120 ms неполный кадр отбрасывается; остаток, пролежавший дольше 40 ms, дополняется и отправляется. Не меняйте размер заголовка без изменения страницы слушателя (`src/network/static/app.js`) и `tests/websocket_wire_format.rs`.

Текстовые сообщения от сервера:

| `type` | Формат | Когда |
|--------|-------|------|
| `welcome` | `{"type":"welcome","data":{"client_id":"…","message":"…"}}` | при подключении |
| `format` | `{"type":"format","data":{"sample_rate":48000,"channels":2,"format":"opus","frame_size":960}}` | вместе с первым кадром; сразу после `welcome`, если поток уже запущен; на `get_format`, когда поток уже запущен (до этого ответа нет) |
| `now_playing` | `{"type":"now_playing","scene":"…"\|null,"track":"…"\|null}` | при подключении и при изменении, не чаще одного раза в 200 ms; в названиях только имена, не более 120 символов |
| `pong` | `{"type":"pong"}` | ответ на `ping` |

Сообщения клиента: `{"type":"ping"}` и `{"type":"get_format"}`. Неизвестные типы и двоичные сообщения игнорируются. Сервер также отправляет ping уровня WebSocket каждые 30 s. Сессия закрывается с кодом **4001**, когда ключ доступа отозван, и закрывается без кода, когда сервер останавливается. При `server.tls` тот же путь — `wss://`.

### Управление ведущего: `/ws/control?g=<token>`

Кадры — это текстовые объекты JSON размером не более 4096 байт. Клиент отправляет `cmd` и необязательный `req`. Сервер отправляет `snapshot` (`rev`, `state`) сразу после подключения и после каждого изменения, `ack` (`{"type":"ack","req":…,"ok":true}`) и `error` (`message`; оба возвращают `req`), а также `pong` (возвращает `req`). На любое неизвестное сообщение отвечается `error`, и сокет остаётся открытым.

Команды клиента: `ping`, `state`, `play`, `stop`, `volume`, `loop`, `master`, `stop_all` (необязательный `fade_ms`), `scene`, `stop_scene`, `stinger`, `duck`, `bus`, а также семейство `playlist_*` (`playlist_start`, `playlist_stop`, `playlist_pause`, `playlist_resume`, `playlist_toggle`, `playlist_next`, `playlist_prev`, `playlist_seek`, `playlist_shuffle`, `playlist_repeat`). REST-аналоги находятся в `/api/control/*`. Ограничения: не более 16 клиентов одновременно (17-й получает HTTP 503), 100 команд в секунду на клиента (лишние получают одну `error` и отбрасываются); сервер пингует простаивающих клиентов каждые 25 s и отключает клиента, который молчит 75 s. Сокет закрывается с кодом **4003**, когда токен ведущего отозван. Оболочка страницы (`/control`, `/control.js`, `/control.css`) отдаётся всем; всё, что читает или меняет Board, требует токена ведущего или подключения с петлевого адреса (loopback). Правила доступа описаны в документации модуля `src/network/control.rs`.

<a id="data-model-and-configuration"></a>
## Модель данных и конфигурация

### Модель библиотеки

`[library]` в `config.toml` отражает структуру `Library` в памяти (`src/gui/groups.rs`):

- **groups**: `id`, `name`.
- **sounds**: `id`, `path` (обязательно), `name`, `volume`, `looped`, `group`, `tags`, `gain_db`, `bus`, `oneshot_stinger`, `pan`.
- **scenes**: `id`, `name`, `color`, `fade_in_ms`, `fade_out_ms`, `curve`, `stop_others`, `items`, необязательные `emitters` и `playlist`.
- **playlists**: `id`, `name`, `items`, `shuffle`, `repeat`, `crossfade_ms`, `bus`.

Сцены, плейлисты и горячие клавиши ссылаются на звуки по **id** (строка UUID), но никогда по пути. Собственный id звука в движке (`SoundId`) отделён от этого и сопоставляется в `sync_director`. Комплекты (`bundle.toml`) содержат группы, звуки, сцены и плейлисты и при импорте сохраняют id.

### Справочник по конфигурации

Схема находится в `src/config.rs`; значения по умолчанию — это значения по умолчанию serde. Каждый раздел необязателен.

| Параметр | По умолчанию | Значение |
|-----|---------|---------|
| `[server] host`, `port` | `"0.0.0.0"`, `8080` | адрес привязки (IP-адрес, а не имя хоста) и порт от 1 до 65535 |
| `[server] upnp` | `true` | просить роутер пробросить порт (только IPv4; пропускается при привязке к петлевому адресу) |
| `[server] access_token` | генерируется при первом запуске, если ключа нет | ключ доступа; `""` позволяет слушать любому, кто может подключиться к порту |
| `[server] gm_token` | генерируется при первом запуске, если ключа нет | токен ведущего; `""` оставляет панель доступной только с этого компьютера |
| `[server] tls`, `tls_cert`, `tls_key` | `false`, не задано, не задано | HTTPS; собственная пара PEM, оба файла или ни одного (один без второго — ошибка запуска) |
| `[audio] buffer_size` | `960` | буфер устройства в кадрах; `0` — драйвер выбирает сам; от 64 до 8192, другие значения возвращаются к 480 с предупреждением в журнале |
| `[audio] sample_rate`, `channels` | `48000`, `2` | запрошенная частота дискретизации устройства (от 8000 до 192000) и число каналов (от 1 до 8); значения вне диапазона возвращаются к 48000 и 2. Микс и аудиопоток остаются стерео 48 kHz |
| `[audio] master_volume` | `0.8` | общий уровень; должен быть от 0.0 до 1.0; значение вне диапазона останавливает запуск с ошибкой микшера |
| `[audio] normalize`, `normalize_target_lufs` | `false`, `-18.0` | нормализация громкости; целевое значение ограничивается диапазоном от -60 до 0 |
| `[audio] duck_amount` | `0.3` | уровень, до которого опускаются приглушаемые шины; ограничивается диапазоном от 0.0 до 1.0 (`1.0` = без эффекта) |
| `[audio] duck_attack_ms`, `duck_release_ms` | `200`, `800` | время приглушения |
| `[audio] duck_buses` | `["music", "ambience"]` | шины, которые приглушаются |
| `[audio] stream_threshold_secs` | `60` | файлы длиннее порога читаются потоком с диска; `0` выключает потоковое чтение с диска |
| `[audio] output_device`, `preview_device` | не задано | имена устройств; «не задано» = системное устройство по умолчанию / основной вывод; имя, которое не найдено, возвращается к значению по умолчанию |
| `[logging] level`, `file_logging` | `"info"`, `false` | `RUST_LOG` переопределяет уровень; `file_logging` также записывает `bardwave.log` в корневой каталог данных |
| `[gui] reduce_motion`, `global_hotkeys` | `false`, `false` | анимации; глобальные горячие клавиши |
| `[gui] recordings_dir`, `record_float32` | не задано, `false` | папка WAV (по умолчанию `recordings/` в каталоге данных); 32-битный float |
| `[gui] check_updates`, `last_update_check` | `false`, `0` | ежедневная проверка обновлений; Unix-время последней проверки |
| `[gui] ui_scale` | `1.0` | ограничивается диапазоном от 0.8 до 1.6 (нечисловое или бесконечное значение даёт 1.0) |
| `[gui] onboarding_done` | `false` | карточка первого запуска пройдена |

Значения по умолчанию для отдельных записей: звук — `volume` `1.0`, `looped` `false`, `bus` `"ambience"`, `pan` `0.0`, `gain_db` `0.0`; сцена — `fade_in_ms` и `fade_out_ms` `2000`, `curve` `"equal_power"` (или `"linear"`), `stop_others` `true`; элемент сцены — `volume` `1.0`, `start` `"on_enter"` (или `"manual"`), `delay_ms` `0`; эмиттер — `min_interval_ms` `20000`, `max_interval_ms` `60000`, `volume` `1.0`, `max_overlap` `2`, `volume_jitter` и `pan_jitter` `0.0`; плейлист — `repeat` `"all"` (`"off"`, `"one"`), `crossfade_ms` `2000`, `bus` `"music"`; таймер — `trigger` `{ after_ms = 600000 }`, `enabled` `true`. Шины: `music`, `ambience`, `sfx`.

Действия горячих клавиш и таймеров помечаются полем `kind`. Виды горячих клавиш: `sound`, `scene`, `playlist` (каждый с `target`), `stop_all`, `stop_scene`, `master_up`, `master_down`, `master_mute`, `duck_toggle`, `duck_hold`, `next_track`, `prev_track`, `pause_music`. Виды таймеров: `activate_scene` (`scene`), `stop_scene`, `play_stinger` (`sound`), `stop_all` (`fade_ms`), `start_playlist` (`playlist`), `stop_playlist`, `next_track`, `pause_music`, `resume_music`. Условие срабатывания таймера — `{ after_ms = … }` или `{ every_ms = … }`; самый короткий интервал — 100 ms. Поле `key` горячей клавиши — это модификаторы и одна клавиша, соединённые через `+`; `canonical_hotkey` приводит его к нормальному виду (`"shift+ctrl+a"` становится `"Ctrl+Shift+A"`).

### Правила совместимости

- У каждого нового поля есть значение по умолчанию serde, поэтому старые файлы загружаются без изменений. Изменение схемы требует случая в `tests/config_compat.rs` (он гарантирует, что файлы v1.4.0 продолжают загружаться).
- Звуку, сцене или плейлисту, у которого `id` отсутствует, пуст, не является UUID или повторяется, при загрузке назначается новый UUID (`ensure_ids`), который записывается при следующем сохранении. Ссылки внутри библиотеки и горячие клавиши следуют за заменённым id, написанным вручную. Таймеры не переназначаются.
- Отсутствующий `config.toml` даёт значения по умолчанию. `config.toml`, который не удаётся разобрать, останавливает приложение с ошибкой (диалог в консоли, stderr при `--server-only`). Его никогда не заменяют значениями по умолчанию, потому что следующее сохранение перезаписало бы библиотеку. (Комментарий документации к `Config::load` всё ещё говорит, что происходит возврат к значениям по умолчанию; `main.rs` так не делает.)
- Сохранение полностью перезаписывает файл из модели в памяти (`toml::to_string_pretty`), поэтому комментарии и порядок параметров в отредактированном вручную файле не сохраняются.
- Таймеры сохраняются только как описания и всегда запускаются остановленными.
- `[[hotkeys]]` и `[[timers]]` — это настройки консоли. Их нет в комплектах, и они не работают с `--server-only`.

### Каталог данных

`src/paths.rs` выбирает каталог с помощью чистой функции `choose_data_dir`:

| Ситуация | Каталог |
|-----------|-----------|
| `portable.flag` рядом с исполняемым файлом | папка программы |
| `config.toml` рядом с исполняемым файлом (в Windows — только если эта папка доступна для записи) | папка программы |
| папка исполняемого файла доступна для записи и не находится внутри `.app` macOS | папка программы |
| иначе, macOS | `~/Library/Application Support/Bardwave` |
| иначе, Windows | `%APPDATA%\Bardwave` |
| иначе, Linux и другие Unix | `$XDG_DATA_HOME/bardwave` или `~/.local/share/bardwave` |

Это корневой каталог. Если системное расположение определить нельзя (нет `HOME` или `APPDATA`), используется папка программы. `--profile <name>` (или `--profile=<name>`) переносит `config.toml` и `bardwave-library/` в `profiles/<name>/` внутри корня; журнал, `tools/` и `recent.toml` остаются в корне и общие. `--profile default` означает корневой профиль. Имена — от 1 до 32 символов: буквы, цифры, пробел, `-` и `_`; `default` и имена устройств Windows, например `CON`, не принимаются. Некорректное имя или папка профиля, которую невозможно создать, показывают ошибку и завершают работу с кодом 2.

> **Примечание:** Выбор каталога для каждой ОС проверяется модульными тестами на любом хосте, но на каждой ОС не проверен **(не проверено)**.

<a id="build-and-run"></a>
## Сборка и запуск

Требования, как указано в `Agent.md` и `README.md`: Rust 1.85 или новее (в `Cargo.toml` нет `rust-version`, поэтому Cargo этого не проверяет; не проверено). Opus реализован на чистом Rust (`rusty-opus`), поэтому CMake или компилятор C не нужны. В Debian или Ubuntu CI устанавливает `pkg-config libgtk-3-dev libasound2-dev libxkbcommon-dev libxcb-render0-dev libxcb-shape0-dev libxcb-xfixes0-dev libssl-dev`. `ffmpeg` нужен для импорта с YouTube на macOS и Linux; в Windows он загружается при первом использовании.

```bash
cargo build --release --locked
cargo run --release                              # console
cargo run --release -- --server-only             # headless, serves /control
cargo run --release -- --profile "Camp 1"        # campaign profile
cargo build --release --locked --features midi   # optional MIDI module
```

Единственные флаги — `--server-only` и `--profile`; остальные аргументы игнорируются. Исполняемый файл — `target/release/soundshared` (`soundshared.exe`). Релизная сборка для Windows использует подсистему GUI: при запуске из терминала она подключается обратно к этому терминалу, а `--server-only`, запущенный из Explorer, открывает собственное окно консоли Windows. В Windows `build.bat` оборачивает частые команды (`release`, `test`, `clean`, `fmt`, `clippy`).

<a id="tests-and-the-layout-harness"></a>
## Тесты и проверка раскладки

```bash
cargo test --all-targets --locked
cargo clippy --all-targets --locked
cargo clippy --all-targets --locked --features midi
cargo fmt --all --check
```

В `src/` и `tests/` примерно 1 190 атрибутов тестов (1 131 `#[test]` и 60 `#[tokio::test]`; это подсчёт по тексту, а не запуск); `Agent.md` и `README.md` всё ещё пишут «~780». В `tests/` 33 файла, среди них `config_compat.rs`, `websocket_wire_format.rs` и `gm_control_auth.rs`. `docs_gm_token.rs` читает `README.md`, `packaging/README.txt` и `packaging/config.toml`, поэтому при правках следите, чтобы формулировки про `gm_token` и `?g=` оставались верными.

Раскладка консоли проверяется в режиме без окна. `src/gui/layout_check.rs` выполняет один полный кадр консоли (`GuiApp::draw_frame`) через `egui::Context::run`, читает нарисованные фигуры и сообщает:

- `ClipOverflow`: текст обрезан своей областью отсечения больше чем на 1 px;
- `Overlap`: тексты перекрываются больше чем на 2 px по обеим осям;
- `OffScreen`: нарисованное содержимое выходит за пределы окна;
- `IdClash`: предупреждение egui о том, что «two widgets share an id»;
- `Hidden`: обязательный элемент управления обрезан, уехал за пределы прокрутки или не нарисован. Обязательные элементы: «Stop all», «Mute» и «Add Sound», а также «Stop Server» и «Copy Link», пока сервер запущен, или «Start Server», пока он остановлен.

Вертикальное обрезание по краю области прокрутки не считается ошибкой (наполовину видимая строка — обычное поведение при прокрутке); горизонтальное — никогда. Тест `the_console_has_no_layout_violations_in_any_size_scale_and_state` проверяет пять размеров окна (от 900 на 600 до 1600 на 900) при масштабе интерфейса 1.0 и 1.3 в пяти состояниях (пустая библиотека или библиотека с длинными именами, 0 или 2 сцены, сервер остановлен или запущен), поэтому регрессия провалит `cargo test`. `layout_probe.rs` предоставляет вспомогательные функции для текстовых блоков, которые тесты верхней панели, музыки и панели сцен используют для собственных проверок ширины. Проверка раскладки (layout harness) не видит текст, перетекающий на соседнюю плашку, подсказки и открытые диалоги. Она не обращается к аудиоустройству, сети и вашей конфигурации.

<a id="packaging-and-releases"></a>
## Упаковка и релизы

| Рабочий процесс (workflow) | Триггер | Результат |
|----------|---------|--------|
| `ci.yml` | push и pull request в `main`; вручную | fmt, clippy, тесты и clippy для функции midi на Ubuntu, Windows, macOS; предупреждения считаются ошибками (`RUSTFLAGS` из `setup-rust-toolchain`) |
| `release.yml` | push в `main`, когда тег `v<Cargo.toml version>` новый; или вручную с подходящей версией | тесты; zip для Windows x86_64 и архив tar.gz для Linux x86_64 (ubuntu-22.04); git-тег и релиз; проверка, что `Cargo.lock` содержит ту же версию |
| `release-extras.yml` | релиз опубликован или после успешного запуска `Release`; или вручную с тегом | установщик Inno Setup (`packaging/windows/bardwave.iss`) и отдельный `.exe`; AppImage и `.deb` (cargo-deb); дымовые тесты; `SHA256SUMS` |
| `release-macos.yml` | релиз опубликован или вручную с тегом | универсальный (aarch64 и x86_64) `Bardwave.app` в `.dmg` и его `.sha256`; обновляет `SHA256SUMS` |

Релиз, созданный `release.yml` встроенным токеном, не запускает событие `release: published`, поэтому `release-macos.yml` для него сам не стартует: запустите его вручную с тегом. У `release-extras.yml` для этого случая есть собственный триггер `workflow_run`.

Исходники в `packaging/`: `README.txt` (краткое руководство по старту) и `config.toml` (пример с комментариями) попадают в zip и архив tar.gz; `windows/bardwave.iss`; `linux/` (`build-appimage.sh`, `bardwave.desktop`); `macos/` (`build-app.sh`, `make-dmg.sh`, `sign-notarize.sh`, `entitlements.plist`, `README.md`). `.deb` описывается секцией `[package.metadata.deb]` в `Cargo.toml` (пакет `bardwave`, бинарный файл устанавливается как `/usr/bin/bardwave`).

> **Предупреждение:** Не меняйте `version` в `Cargo.toml` в рамках не относящейся к делу работы. Push в `main` публикует релиз для этой версии, а выбор версии — решение владельца. `Cargo.lock` должен содержать ту же версию (после повышения версии выполните `cargo build` и закоммитьте оба файла).

> **Примечание:** Подпись и нотаризация macOS выполняются, только если заданы секреты Apple; без них прикрепляется сборка с ad-hoc-подписью. Установщики, приложение macOS и рабочие процессы релизов не запускались на реальных машинах **(не проверено)**; см. `CHANGELOG.md`.

<a id="contributing-and-code-style"></a>
## Участие в разработке и стиль кода

Держите документацию достоверной. Изменение функции обновляет `README.md`, `Agent.md` и `CHANGELOG.md` одновременно. Перед большим pull request откройте issue.

- Используйте типизированные команды. Не делите изменяемое состояние между GUI, движком и сетью.
- Никогда не блокируйте поток отрисовки и в аудио-колбэке только микшируйте.
- Ссылайтесь на звуки по id.
- Новым полям конфигурации назначается `#[serde(default)]`, а изменение схемы получает тест в `tests/config_compat.rs`.
- Используйте `anyhow::Result` и `thiserror`. Паники проходят через хук в `main.rs`. Ведите журнал через `tracing` (`RUST_LOG` переопределяет `[logging] level`); никогда не записывайте в журнал `?k=`, `?g=` или значения токенов.
- Запускайте `cargo fmt --all`. Держите clippy без предупреждений и следите, чтобы функция `midi` продолжала собираться.

Pull request направляются в `main`. Открытые pull request запускают CI, но не создают релизы.

### Симптомы и причины

| Симптом | Причина | Где искать |
|---------|-------|---------------|
| Диалог ошибки при запуске, приложение не открывается | `config.toml` не разбирается | сообщение называет файл; исправьте его, приложение никогда его не сбрасывает |
| Диалог ошибки (или stderr) и код выхода 2 при запуске | некорректное имя `--profile` или папку профиля невозможно создать | `src/profiles.rs`, `src/paths.rs` |
| В настольном приложении тихо, но игроки слышат аудиопоток | не удалось открыть ни одно локальное устройство вывода; движок работает в режиме без окна | строка состояния показывает `Local off — headless (network only)` или `Local failed — <error>`; `main.rs`, `top_bar.rs` |
| Слушатель получает закрытие с кодом 4001 | ключ доступа был пересоздан | `network/access.rs`; отправьте игрокам новую ссылку |
| Страница ведущего возвращает 401, затем 429 | неверный токен `?g=`; после 10 неудач за минуту | `network/access.rs` (`GM_MAX_FAILURES`); подождите минуту |
| `/ws/control` закрывается с кодом 4003 | токен ведущего отозван | перезагрузите страницу по текущей ссылке с `?g=` |
| Сервер не запускается, статус показывает «Error», а кнопка становится «Retry Server» | ошибка привязки, например занятый порт, или ошибка настройки HTTPS | `main.rs`, функция `start_listener` возвращает ошибку в GUI через канал ответа команды |
| Запуск HTTPS не удаётся | сертификат или ключ не читаются или не совпадают, либо задан только один из двух | [Руководство по HTTPS](./https.md), таблица устранения неполадок |

### Известные ограничения

- Горячие клавиши и таймеры не работают с `--server-only`.
- HTTPS выключен по умолчанию; пока он не включён, ключи в ссылках передаются по обычному HTTP. См. [Руководство по HTTPS](./https.md).
- Нормализация громкости пропускает файлы, читаемые потоково с диска.
- MIDI подключается через необязательную функцию `midi` (по умолчанию выключена) и не связан с консолью; привязки MIDI сообщаются как недоступные.
- Глобальные горячие клавиши на Linux работают только в X11 и **(не проверено)** на macOS. Переключение аудиоустройств в Windows и Linux **(не проверено)**.
- Светлой темы нет (палитра — константы в `gui/theme.rs`), и нет громкости отдельных шин для игроков (один общий аудиопоток).
