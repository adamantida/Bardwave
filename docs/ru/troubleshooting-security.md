## Устранение неполадок

### С чего начать

Сначала посмотрите на панель **Network Server** (сетевой сервер). Состояние показано заглавными буквами:

| Состояние | Строка под ним | Значение |
|---|---|---|
| `Live` | `Broadcasting to N listeners` | Сервер работает. |
| `Starting` | `Binding the listen socket` | Запуск выполняется. |
| `Error` | Текст ошибки, обрезанный до 34 символов | Сервер не смог запуститься. Полный текст находится в журнале. |
| `Off Air` | `Server stopped` | Сервер не запущен. |

Под **Listen URL** (адрес прослушивания) может находиться строка `Local ...`, строка `Internet ...` и янтарные примечания (`VPN active ...`, `Firewall: ...`). Порт и адрес привязки редактируются в **CONFIGURATION** (конфигурация), только когда сервер остановлен.

**Где журнал?** По умолчанию журнал выводится только в терминал, а релизная сборка Windows не имеет окна консоли. Чтобы сохранять журнал, задайте `file_logging = true` в `[logging]`. Тогда Bardwave также записывает `bardwave.log` в каталог данных (корневой каталог данных, если используются профили, — общий для всех профилей). `level` по умолчанию равен `info` (`trace`, `debug`, `info`, `warn` или `error`). Переменная окружения `RUST_LOG` заменяет `level`, если содержит корректный фильтр. В журнале никогда не бывает токена ведущего (game master, GM), но ключ доступа может в нём появиться (см. [Смена ключей](#rotating-keys)).

```toml
[logging]
level = "info"
file_logging = true   # writes bardwave.log in the data folder
```

### Нет звука

Проверьте строку состояния под выпадающим списком **Output** (вывод) в разделе **AUDIO OUTPUT** (вывод звука). Она показывает `Active: <device> - 48000 Hz, 2 ch` или `Error: ...`.

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Звук идёт не на ту звуковую карту. В строке состояния есть примечание, например `output device "X" not found; using the system default` | `[audio] output_device` указывает устройство, которое не найдено. Bardwave переходит на системное устройство по умолчанию. Сначала ищется точное совпадение, затем — без учёта регистра и пробелов по краям. | Выберите устройство заново в выпадающем списке или удалите `output_device`. Подключите устройство и нажмите **Refresh devices** (обновление списка устройств). |
| `Error: no output device opened (network only)` | Не удалось открыть ни одну звуковую карту. Игроки всё равно получают поток. | Проверьте системное устройство вывода, затем нажмите **Refresh devices**. |
| Ничего не играет, сообщения нет | Общая громкость (master) стоит на нуле (при выключенном звуке консоль показывает **Unmute** на полосе MASTER OUTPUT). Или фейдер одной из шин (bus) — **Music**, **Ambience**, **Sfx**, раздел MIX — стоит на нуле. Или приглушение (ducking) зафиксировано: кнопка **Duck** показывает **Ducked**, из-за чего снижается громкость музыки и атмосферы. | Нажмите **Unmute**, поднимите общую громкость и фейдеры, снова нажмите **Ducked**, чтобы снять приглушение. |
| Строка звука янтарная, с предупреждением | Файл отсутствует. | См. [Отсутствующие файлы](#missing-files). |
| Игроки ничего не слышат, консоль играет | В их ссылке нет ключа, или они не нажали **Establish Link** (установка связи). Странице слушателя нужно нажатие, чтобы запустить звук. | Отправьте полную ссылку с `?k=<key>` (**Copy Link**, копирование ссылки) и попросите их нажать **Establish Link**. |
| В потоке нет предпрослушивания (preview) в наушниках | Предпрослушивание по замыслу никогда не попадает к игрокам. | Слушайте предпрослушивание только на этом компьютере. |
| Предпрослушивание играет через основной вывод | `[audio] preview_device` не задан или устройство не найдено (тогда предпрослушивание идёт через основной вывод с примечанием). | Укажите название устройства для наушников. |

`master_volume` при запуске равен `0.8` и читается из `config.toml`. Общий фейдер консоли и фейдеры шин в файл не записываются. Чтобы изменить начальный уровень, отредактируйте `master_volume` (число от `0.0` до `1.0`).

```toml
[audio]
output_device = "USB Headphones"    # main mix; omit for the system default
preview_device = "Built-in Output"  # previews only
master_volume = 0.8
```

### Треск и обрывы

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Щелчки или треск на консоли | Буфер звуковой карты слишком мал для этого драйвера. | Увеличьте `buffer_size`, например до `1920`, и перезапустите Bardwave (не проверено). |
| Консоль игнорирует значение | `buffer_size` вне диапазона `0` или `64`-`8192`. Журнал выдаёт предупреждение, и используются `480` кадров (а не значение `960` по умолчанию в файле). | Используйте `0` (значение драйвера по умолчанию) или значение из диапазона. |
| `sample_rate` или `channels` игнорируются | Вне диапазона (`8000`-`192000` Hz, `1`-`8` каналов). Журнал выдаёт предупреждение, и используется стерео `48000` Hz. | Используйте значение из диапазона. |
| В строке состояния сказано, что формат устройства отличается | У карты нет режима 48 kHz stereo. Микс для устройства передискретизируется или преобразуется. Поток игроков не затрагивается. | Обычно ничего. Выберите другое устройство, если звук плохой. |
| Слушатели слышат пропуски по Wi-Fi | Потери в сети. Страница слушателя переподключается через 1, 2, 4, 8, а затем через 15 секунд, показывает `Reconnecting #N` и качество связи (задержка, буфер, потеря пакетов за 10 секунд), а также подсказку `Weak network`. Сервер отбрасывает кадры для клиента, у которого буфер отправки заполнен (100 пакетов, около 2 секунд). | Подойдите ближе к роутеру или используйте кабель. |

В разделе **AUDIO OUTPUT** показаны действующие значения, например `buffer: 960 frames (20.0 ms) - 48000 Hz - 2 ch`. Там они доступны только для чтения.

```toml
[audio]
buffer_size = 1920   # frames per channel; default 960 (20 ms at 48 kHz); 0 = driver default
```

> **Примечание:** Больший буфер добавляет задержку к выводу консоли. Значение читается один раз при запуске, поэтому меняйте по одному значению за раз и перезапускайте Bardwave. Пакеты, отправляемые игрокам, всегда содержат 960 кадров (20 ms) аудио Opus независимо от `buffer_size`.

### Игроки не могут подключиться

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `Off Air` / `Server stopped` | Сервер не запущен. | Нажмите **Start Server** (запуск сервера). |
| Состояние `Error` | Не удалось занять сокет прослушивания, часто потому, что порт уже занят. | Измените **Port** (порт) в «CONFIGURATION», пока сервер остановлен, затем нажмите **Retry Server** (повторить запуск сервера). |
| `Port must be 1–65535` или `Bind must be an IP address` в разделе CONFIGURATION | Значение недопустимо. Последнее корректное значение остаётся в силе. «Bind Address» (адрес привязки) принимает только IP-адрес, а не имя хоста. | Введите корректное значение. |
| Страница открывается, `Access Denied`, `This link has no access key` | В ссылке нет ключа доступа. | Нажмите **Copy Link** и отправьте эту ссылку. |
| Страница открывается, `Access Denied`, `This link is no longer valid: the GM issued a new access key` | Ключ заменили после того, как ссылкой поделились (код закрытия `4001`). | Отправьте новую ссылку. |
| Страница открывается и простаивает | Страница ждёт нажатия. | Нажмите **Establish Link**. |
| `Link Error`, `Connection failed. Check the server.` | Не удалось установить соединение. | Проверьте, что сервер запущен и адрес указан верно. |
| Страница открывается без оформления, значки пропали | Страница слушателя загружает Tailwind, значки и шрифты с `cdn.tailwindcss.com`, `code.iconify.design` и `fonts.googleapis.com` в браузере игрока. Устройство без интернета не может их загрузить (как при этом выглядит страница, не проверено). | Дайте устройству доступ в интернет или используйте устройство, у которого он есть. |
| Подключается только этот компьютер | `host` равен `127.0.0.1` или `::1`. Привязки к петлевому адресу (loopback) никогда не пробрасываются. | Задайте для **Bind Address** значение `0.0.0.0` (`host = "0.0.0.0"`), пока сервер остановлен. |
| Никто из локальной сети не подключается, macOS | На запрос доступа к локальной сети ответили «Don't Allow». | System Settings > Privacy & Security > Local Network (не проверено на Mac). |
| Локальная сеть работает, игроки из интернета не подключаются | UPnP, второй NAT, VPN или брандмауэр. | См. разделы ниже. |

```toml
[server]
host = "0.0.0.0"   # every IPv4 network of this PC
port = 8080
```

### Неверный адрес в локальной сети

Bardwave собирает все адреса, которыми владеет машина, и оценивает их. Приоритет у частных диапазонов локальной сети (`192.168.x.x`, затем `10.x.x.x`, затем `172.16.0.0/12`, где обычно находятся Docker и WSL). Далее идут публичные адреса, а в последнюю очередь — CGNAT (NAT провайдера) (`100.64.0.0/10`, его использует Tailscale). Диапазон тестирования (benchmarking, `198.18.0.0/15`, его используют адаптеры прокси в режиме TUN), link-local, петлевой и зарезервированные диапазоны никогда не выбираются. В macOS и Linux пропускаются адаптеры с виртуальными именами (например, `utun`, `docker`, `veth`, `br-`, `tun`, `tap`, `wg`, `tailscale`, `zt`). В Windows пропускаются туннельные адаптеры и адаптеры loopback. Привязка к подстановочному адресу (wildcard) объявляет только адрес своего семейства. Если ни один адрес не подходит, ссылка использует петлевой адрес, который игроки открыть не могут.

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| В ссылке `127.0.0.1` | Не найден пригодный адрес локальной сети, или `host` — петлевой адрес. | Проверьте сетевое подключение. Или введите адрес этого компьютера в локальной сети в **Bind Address** (адрес привязки). |
| Ссылка показывает адрес, который не относится к вашей локальной сети (например, `172.x.x.x` от Docker или WSL, `100.x.x.x` от Tailscale) | Это был лучший найденный адрес. | Введите адрес, который должны использовать игроки, в **Bind Address**, пока сервер остановлен. Явно указанный адрес объявляется как есть. Привязка к нему также ограничивает запрос UPnP этим интерфейсом. |
| Адрес в ссылке верный, но игроки всё равно не подключаются | Брандмауэр, VPN или устройства в разных сетях (например, гостевой Wi-Fi). | См. [Брандмауэр](#firewall) и [VPN и прокси-инструменты](#vpn-and-proxy-tools). |

Строка `Local ...` под «Listen URL» не является адресом локальной сети. Она всегда содержит `127.0.0.1` и порт и нужна, чтобы открыть страницу на этом компьютере, даже если определение адреса неверно. Определение не отправляет пакеты: оно лишь спрашивает у системы, какой адрес она использовала бы для маршрута. Ссылку всегда можно составить вручную: `http://<LAN address of this PC>:<port>/?k=<key>`.

### Сбой UPnP и второй NAT

`[server] upnp = true` — значение по умолчанию. Bardwave в фоновом режиме просит роутер пробросить TCP-порт (только UPnP, только IPv4). Ссылка для локальной сети появляется сразу, и сервер никогда не ждёт роутера. Строка `Internet` не появляется, если `upnp = false` или если `host` — петлевой адрес или адрес IPv6.

| Строка «Internet» в консоли | Значение | Что делать |
|---|---|---|
| `Internet: asking the router…` | Выполняется первая попытка. | Подождите несколько секунд. |
| `Internet: no UPnP router` | Ни один роутер не ответил или отказал. Bardwave повторяет попытку каждые 30 секунд. Наведите курсор на строку, чтобы прочитать последнюю причину. | Включите UPnP на роутере. Ручная настройка проброса возможна (не проверено). |
| `Internet: blocked by a second NAT (<address>)` | Адрес, который сообщает роутер, не публичный (частный, CGNAT и подобный), поэтому перед ним стоит ещё один NAT. | Пробросьте порт на вышестоящем устройстве или попросите у провайдера публичный адрес. |
| `Internet http://<address>:<port>` (`https://`, если HTTPS включён) | Проброс публичный. Щёлкните строку, чтобы скопировать её. | Проверьте с телефона через мобильную сеть. Открытие изнутри собственной сети может не работать на роутерах без NAT loopback. |

Запрашивается срок аренды (lease) 2 часа. Он продлевается на половине срока, который выдал роутер (но не реже чем каждые 60 секунд). Постоянная аренда перепроверяется каждые 30 минут. Если роутер отвечает ошибкой `725` (только для постоянных аренд), Bardwave запрашивает постоянную аренду снова. Если он отвечает `718` (порт уже переадресован на другой хост), Bardwave пробует другой внешний порт, до четырёх раз, поэтому ссылка через интернет может содержать порт, отличный от вашего. Проброс удаляется при **Stop Server** (остановка сервера). Эти ответы роутеров обрабатываются только в коде и в модульных тестах (не проверено на реальных роутерах).

```toml
[server]
upnp = false   # LAN play only; no router requests
```

<a id="vpn-and-proxy-tools"></a>

### VPN и прокси-инструменты

VPN с полным туннелем отправляет ответы игрокам из интернета в туннель, поэтому они не могут подключиться. Консоль показывает янтарное примечание, когда маршрут по умолчанию не идёт через выбранный адрес локальной сети:

> `VPN active (<address>): internet players can't connect until it is off`

Игра в локальной сети продолжает работать. Перед приглашением игроков из интернета выключите VPN или исключите из него Bardwave (не проверено с реальными VPN-клиентами). Прокси в режиме TUN (Clash, xray, sing-box) используют диапазон тестирования, который Bardwave никогда не объявляет. Ссылка для локальной сети остаётся верной, но то же примечание, вероятно, появится (не проверено с этими инструментами). См. [Неверный адрес в локальной сети](#wrong-lan-address).

<a id="firewall"></a>

### Брандмауэр

| Платформа | Что происходит | Что делать |
|---|---|---|
| Windows | При запуске сервера Bardwave добавляет входящее правило с именем `Bardwave TCP <port>` для TCP, профиль `any`. Правило заменяется при каждом запуске. Для его создания нужны права администратора. Установщик может добавить эквивалентное правило для TCP `8080` (частные и публичные сети). | Без прав администратора консоль показывает `Firewall: port <port> not opened - allow Bardwave for public networks or run as admin`. Windows может спросить при первом прослушивании: разрешите Bardwave для **частных и публичных** сетей. |
| macOS | Bardwave не добавляет правил брандмауэра. Приложение объявляет использование локальной сети. | Разрешите входящие подключения и доступ к локальной сети, когда система спросит (не проверено на Mac). |
| Linux | Bardwave не добавляет правил брандмауэра. | Если брандмауэр активен, откройте TCP-порт прослушивания самостоятельно (по умолчанию 8080), например, с помощью `ufw` или `firewalld` (не проверено). |

> **Предупреждение:** Не отключайте брандмауэр для проверки. Откройте только порт прослушивания.

### Сбой загрузки с YouTube

Кнопка **YouTube** в библиотеке открывает диалог **Add From YouTube** (добавление с YouTube). После вставки ссылки нажмите **Add** (добавить). Принимаются формы `watch?v=`, `youtu.be/`, `music.youtube.com/watch?v=`, `/shorts/`, `/embed/`, `/live/` и просто идентификатор из 11 символов. Плейлисты, страницы каналов и другие сайты отклоняются, а ссылка с `&list=` остаётся одним треком. Одновременно выполняется одна загрузка. **Close** (закрыть) закрывает диалог, а загрузка продолжается в фоне. Аудио сохраняется как MP3 (160K) в папку `bardwave-library` каталога данных под именем `<title> [<id>]`. Повторное добавление того же видео использует уже существующий файл.

| Сообщение | Причина | Что делать |
|---|---|---|
| `Not a YouTube video link` | Текст не относится к принятым формам. | Вставьте ссылку на одно видео. |
| `yt-dlp not found — downloading it once (~24 MB)…` | `yt-dlp` загружается с GitHub при первом использовании. | Подождите. Загрузка кэшируется в папке `tools` каталога данных. |
| `Failed to download yt-dlp: …` или `Downloaded yt-dlp is only N bytes — aborted` | Нет сети или GitHub вернул ошибку. | Проверьте подключение и повторите попытку. |
| `Neither the Bardwave data folder nor the app-data tools folder is writable…` | Инструмент не удаётся сохранить. | Сделайте каталог данных доступным для записи или поместите `yt-dlp` рядом с Bardwave или в `PATH`. |
| `This platform has no prebuilt yt-dlp…` | Для этой ОС или процессора нет готового файла релиза. Файлы есть для Windows, macOS и Linux. | Установите `yt-dlp` и поместите его в `PATH`. |
| `ffmpeg not found on this system…` | ffmpeg отсутствует. Он загружается автоматически только в Windows (около 100 MB, сборки BtbN). | `brew install ffmpeg` (macOS) или `apt install ffmpeg` (Linux). В Windows поместите `ffmpeg.exe` рядом с `Bardwave.exe`. |
| `yt-dlp failed: …` | YouTube изменился, либо видео недоступно или ограничено по региону. Текст — конец собственного вывода ошибки yt-dlp. | Обновите `yt-dlp` и повторите попытку. |
| `Download finished, but no file for <id> appeared in <folder>` | yt-dlp сообщил об успехе, но файл не записал. | Проверьте папку `bardwave-library` и журнал. |

Bardwave загружает `yt-dlp` только тогда, когда его нет, и никогда его не обновляет. Поиск идёт в таком порядке: рядом с программой, затем `PATH`, затем собственная папка `tools` (и более старая папка инструментов пользователя из предыдущих сборок). Чтобы обновить, замените этот файл более новой сборкой или удалите копию из папки `tools`, чтобы загрузилась новая. Строки прогресса: `Connecting…`, `Fetching video info…`, `Downloading audio… N%` и `Converting to MP3…`. Загруженные инструменты проверяются только на минимальный размер, а не на хеш или подпись. Процесс загрузки в macOS и Linux и загрузка ffmpeg в Windows: не проверено на реальных машинах.

```bash
pip install -U yt-dlp   # if yt-dlp came from pip
brew install ffmpeg     # macOS, when ffmpeg is missing
```

<a id="missing-files"></a>

### Отсутствующие файлы

Файлы, которые переместились, остаются в библиотеке и помечаются как отсутствующие: библиотека показывает янтарный баннер с количеством, а у каждого такого звука есть предупреждение. Нажмите **Locate…** (указать файл заново) у звука (или `LOCATE…` в его строке), чтобы выбрать новый файл. Нажмите **Replace Path Prefix…** (заменить префикс пути) в баннере, чтобы переписать начало каждого пути, когда переместилась целая папка (баннер показывает, сколько путей изменится). **Recheck** (проверить снова) ищет файлы заново. Значок крестика удаляет звук из библиотеки. Сцены, плейлисты и горячие клавиши ссылаются на идентификаторы звуков, а не на пути, поэтому после перепривязки продолжают работать.

### Настройки не сохраняются

`config.toml` находится в каталоге данных, который зависит от платформы:

| Ситуация | Каталог |
|---|---|
| `config.toml` рядом с программой (в Windows — только если эта папка доступна для записи), либо файл `portable.flag` рядом с ней, либо папка программы доступна для записи (и она не внутри `.app` macOS) | Папка программы |
| macOS, в остальных случаях | `~/Library/Application Support/Bardwave` |
| Windows, в остальных случаях (например, `Program Files`) | `%APPDATA%\Bardwave` |
| Linux и другие Unix, в остальных случаях | `$XDG_DATA_HOME/bardwave` или `~/.local/share/bardwave` |

Выбор делается при запуске (не проверено на каждой ОС). С `--profile <name>` файлы `config.toml`, библиотека, `bardwave-library` и папка `tls` переходят в `profiles/<name>/` внутри этой папки. Журнал, папка `tools` и `recent.toml` остаются в корне. Копия программы в доступной для записи папке (папка загрузок, USB-накопитель) хранит собственный `config.toml` рядом с собой, поэтому другая копия той же программы может показывать другие настройки.

Настройки как будто сбросились? Откройте каталог данных из меню **Profile** (профиль) в верхней панели (**Open data folder**) и проверьте, какой `config.toml` вы редактируете. Оставьте один. Файл `portable.flag` рядом с программой хранит данные рядом с ней.

Если `config.toml` не удаётся прочитать, Bardwave показывает `config.toml could not be read` (сообщение в консоли или ошибка в stderr при `--server-only`) и останавливается. Он не запускается со значениями по умолчанию, потому что следующее сохранение перезаписало бы вашу библиотеку. Исправьте файл или уберите его в сторону, чтобы запустить Bardwave со значениями по умолчанию.

### Gatekeeper в macOS

Неподписанная сборка блокируется при первом открытии. Приложение получает ad-hoc-подпись, чтобы работать на Apple Silicon, но подпись и нотаризация для этого проекта не запускались (не проверено).

1. Не открывайте `Bardwave.app` двойным щелчком.
2. Щёлкните правой кнопкой (Control-щелчок), выберите **Open** (открыть), затем снова **Open**.
3. В macOS Sequoia и новее, если запуск всё ещё запрещён: попробуйте открыть его один раз, затем System Settings > Privacy & Security > **Open Anyway**.
4. Или снимите атрибут карантина у файла, скачанного через браузер:

```bash
xattr -dr com.apple.quarantine /Applications/Bardwave.app
```

Дополнительные шаги — в [packaging/macos/README.md](../../packaging/macos/README.md).

<a id="faq"></a>

## FAQ

**Нужен ли HTTPS для домашней игры?**
Нет. `[server] tls` по умолчанию равен `false`, а локальная сеть работает через HTTP. Включите HTTPS, прежде чем отправлять ссылки через интернет. См. [HTTPS](#https).

**Почему в ссылке есть `?k=`?**
Это ключ доступа. Без него поток отклоняется.

**Могут ли игроки открыть панель ведущего по своей ссылке?**
Нет. Ключ доступа не открывает данные панели. Игрок может загрузить пустую оболочку страницы по адресу `/control`, но каждый вызов, который читает или меняет что-либо, требует токен ведущего и получает ответ `401`.

**Как отключить человека, у которого есть ссылка?**
Нажмите значок обновления в строке «ACCESS KEY», затем отправьте новую ссылку.

**Можно ли работать без ключа слушателя?**
Да, с `access_token = ""`. Консоль тогда показывает `ACCESS KEY OFF - ANYONE CAN LISTEN`. Используйте это только в доверенной сети.

**Проверяет ли Bardwave обновления сам?**
Нет. Проверка выключена по умолчанию. **Check for updates** (проверка обновлений) запрашивает GitHub при нажатии. Флажок **Check once a day at start** (`[gui] check_updates = true`) включает автоматическую проверку при запуске, не чаще раза в день. Ничего не загружается и не устанавливается. Проверка не запускалась на опубликованном релизе (не проверено).

**Сохраняется ли общая громкость?**
Используется только значение `[audio] master_volume` из `config.toml` при запуске. Фейдер консоли не сохраняет своё положение.

**Можно ли менять порт, пока сервер работает?**
Нет. **Port** и **Bind Address** редактируются только при остановленном сервере и применяются при следующем запуске.

**Нужен ли игрокам доступ в интернет?**
Для потока в локальной сети — нет. Их браузер всё же загружает для страницы слушателя стили, значки и шрифты с публичных CDN (см. [Что покидает компьютер](#what-leaves-the-machine)). Как страница работает вообще без интернета, не проверено.

**Что игроки видят из моей библиотеки?**
Аудио и название активной сцены и музыкального трека (обрезается до 120 символов, управляющие символы удаляются). Никогда не пути к файлам и не идентификаторы библиотеки.

**Есть ли ограничение на число слушателей?**
В коде нет ограничения на число слушателей. Поведение при большом числе слушателей не тестировалось (не проверено).

**Можно ли запустить без окна?**
Да: `--server-only` (также `--profile <name>`). Горячие клавиши и `[[timers]]` там не работают. Журнал выводит ссылку для игроков с ключом и локальную страницу управления. См. [Справочник по конфигурации](./configuration.md).

<a id="security-model"></a>

## Модель безопасности

### Два ключа: ключ доступа и токен ведущего

| | Ключ доступа | Токен ведущего |
|---|---|---|
| Параметр | `[server] access_token` | `[server] gm_token` |
| Создаётся | При первом запуске, если отсутствует | При первом запуске, если отсутствует |
| Передаётся в | `http://<host>:<port>/?k=<key>` | `http://<host>:<port>/control?g=<token>` или `Authorization: Bearer <token>` |
| Открывает | Аудиопоток (`/ws/audio`) и API статуса (`/api/status`) | Данные и команды панели ведущего (`/api/control/*`, `/ws/control`) |
| Может | Слушать. API статуса сообщает число слушателей и версию. | Запускать, останавливать и зацикливать звуки, задавать громкости, общую громкость (master) и шины, сцены, стингеры (stinger), приглушение, «Stop all» (остановить всё) и плейлист музыки. Читать состояние консоли (названия звуков, сцен и плейлистов, громкости). |
| Не может | Ничего на панели. | Добавлять или удалять файлы, менять настройки, запускать или останавливать сервер, менять ключи, читать файлы или пути. |
| Пустое значение | `""` отключает проверку: слушать может любой | `""` отключает удалённый доступ. Панель отвечает только на этом компьютере. Консоль показывает `Remote panel is off: it opens on this computer only` и кнопку **Create GM key** (создать ключ ведущего). |
| Замена | Значок обновления в строке «ACCESS KEY» | **New key**, затем **Replace key** (**Cancel** сохраняет старый ключ) |

Оболочки страниц (`/`, `/control` и их скрипты и стили) общедоступны и не содержат секретов. Всё, что читает или меняет состояние консоли, требует токен. Ключи состоят из 16 символов `a-z` и `0-9` (около 82 бит) и берутся из источника случайных чисел операционной системы. Сравнения выполняются за постоянное время. Консоль показывает ссылку ведущего замаскированной, с предупреждением **Do not share with players**, и предлагает **Show QR** для телефона. Ответы панели содержат `Cache-Control: no-store` и `Referrer-Policy: no-referrer`, потому что токен может находиться в URL. Панель ведущего отдаётся окном консоли, пока сервер работает, и режимом `--server-only`.

```toml
[server]
access_token = "replace-with-generated-key"  # "" turns the listener check off
gm_token = "replace-with-generated-token"    # "" disables remote panel access
```

> **Предупреждение:** Оба ключа хранятся в `config.toml` открытым текстом. Держите этот файл закрытым и никогда не публикуйте ссылку, содержащую ключ. По обычному HTTP ключи передаются по сети открытым текстом: для интернета включите [HTTPS](#https).

### Локальный доступ

Запрос считается локальным, только если адрес на другом конце сокета — петлевой, в нём нет заголовка прокси, а `Host` равен `localhost`, `127.0.0.1` или `[::1]`. Локальные запросы попадают на панель без токена, с двумя дополнительными проверками:

- Каждое REST-действие должно отправлять заголовок `X-Bardwave-Control`. Без него сервер отвечает `403 missing control header`. Страница с другого сайта не может добавить этот заголовок без предварительного запроса CORS (preflight), который сервер никогда не одобряет. Запрос с токеном сам по себе подтверждает намерение и заголовка не требует.
- Локальное рукопожатие WebSocket, в котором есть `Origin`, должно иметь значение, совпадающее с `Host`. Иначе ответ — `403 cross-origin request`. Рукопожатие без `Origin` (не страница браузера) проходит.

Проверка `Host` блокирует DNS rebinding: страница под другим именем не может использовать доступ без токена с этого компьютера. Телефон в той же локальной сети не является локальным и нуждается в токене ведущего.

### Ограничение частоты запросов

Ограничение частоты применяется только к токену ведущего. У ключа доступа нет блокировки, поэтому его стойкость — 16 случайных символов.

| Правило | Значение | Ответ |
|---|---|---|
| Неверный или отсутствующий токен | Считается для каждого адреса | `401` с `game master token required` |
| Неудачные попытки | 10 за 60 секунд | `429` с `Retry-After` |
| Через прокси на этом компьютере | 60 ошибок за 60 секунд | `429` |
| IPv6 | Считается по префиксу /64 | Как выше |
| Заблокированный адрес | Даже верный токен отклоняется до окончания окна | `429` |

Ответ одинаков для неверного токена, отсутствующего токена и отключённой удалённой панели. На `/ws/control` сообщение может быть размером 4096 байт, подключиться могут не более 16 клиентов (17-й получает `503 too many control clients`), а каждый клиент может отправлять 100 команд в секунду (лишние игнорируются, при этом раз в секунду выводится ошибка `too many commands, slow down`). Неактивным клиентам отправляется ping каждые 25 секунд, а через примерно 75 секунд молчания они отключаются.

### Прокси и туннели

Запрос с заголовком прокси считается удалённым, так же как и запрос, у которого `Host` не является петлевым именем. Проверяются шестнадцать заголовков, в том числе `X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto`, `X-Real-IP`, `Forwarded`, `CF-Connecting-IP`, `True-Client-IP`, `X-Client-IP` и `Via`. Переадресующим адресам никогда не доверяют. Они могут только снизить уровень доверия к запросу.

Туннель на этом компьютере никогда не получает локальный доступ, а без токена не получает ничего. Простые TCP-туннели (`ssh -R`, bore, frp) и прокси, которые переписывают `Host` на `127.0.0.1`, выглядят как собственный браузер ведущего, поэтому используйте их только с заданным `gm_token`. Клиенты за одним прокси делят общий счётчик ограничения частоты, поэтому один враждебный клиент может заблокировать остальных. Выход — сменить токен или работать с панелью на этом компьютере. Эти правила покрыты модульными тестами с имитацией заголовков. Реальное туннельное ПО не пробовали (не проверено).

<a id="rotating-keys"></a>

### Смена ключей

- **Ключ доступа:** нажмите значок обновления в строке «ACCESS KEY». Слушатели со старым ключом отключаются сразу (код закрытия `4001`), а их страница сообщает, что ссылка больше не действительна.
- **Токен ведущего:** нажмите **New key**, затем **Replace key**. Удалённые панели со старым токеном закрываются (код закрытия `4003`). Ссылка для игроков не затрагивается. Панель, открытая на этом компьютере без токена, остаётся подключённой.
- Оба новых ключа сохраняются в `config.toml` при следующей записи настроек.
- Меняйте оба ключа, если ссылка утекла. Ключ может утечь и через журнал: при `--server-only` строка запуска `Listener server available at ...` содержит ссылку для игроков с ключом. Токен ведущего никогда не выводится.

### Импорт комплекта

Комплект библиотеки (`.zip` с `bundle.toml`, формат `bardwave-bundle`, создаётся через **Export…** и читается через **Import…**) может прийти от кого угодно, поэтому модуль импорта относится к нему как к враждебному:

- Запись с абсолютным путём, частью `..` или `.`, пустой частью, обратной косой чертой, двоеточием, управляющим символом или символической ссылкой отклоняет весь архив. Пути внутри `bundle.toml` проверяются так же строго.
- Файлы записываются только внутри выбранной целевой папки, и каждая родительская папка должна вести внутрь неё.
- Извлекаются только файлы, названные в манифесте, и только с расширениями `wav`, `flac`, `mp3`, `ogg`, `m4a` и `aac`. Любой другой файл пропускается с предупреждением, а звук импортируется без аудио.
- Ограничения: 20 000 записей, 100 000 элементов, манифест 16 MB, 2 GB на файл и 8 GB в целом. Заявленные размеры проверяются первыми, а также подсчитываются фактически прочитанные байты.
- Конфликт решается по выбранному правилу: **Keep mine** (пропустить), **Keep both** (переименовать) или **Use the bundle's** (заменить; при этом перезаписываются и существующие аудиофайлы в целевой папке). Пробный прогон ничего не записывает. Если импорт завершился ошибкой или был отменён, созданные им файлы удаляются, а библиотека остаётся без изменений (файл, заменённый по **Use the bundle's**, восстановить нельзя).
- Горячие клавиши не входят в комплект.

<a id="what-leaves-the-machine"></a>

### Что покидает компьютер

По умолчанию ничего никому не отправляется, кроме того, что сервер отдаёт приглашённым игрокам, и запроса к роутеру. Проверка обновлений выключена, пока вы её не включите. Исходящие веб-запросы в коде выполняют только проверка обновлений и загрузка инструментов. Кода телеметрии нет.

| Запрос | Когда | Адресат |
|---|---|---|
| Аудиопоток слушателей | Игроки подключаются | Устройства, которые достигают порта: локальная сеть или интернет, если порт проброшен или переадресован. Аудио в Opus, а также названия сцены и трека. |
| Поиск и проброс UPnP | `upnp = true` (по умолчанию) | Мультикаст в локальной сети, запрос к обычному адресу шлюза, затем ваш роутер |
| Проверка обновлений | **Check for updates** или `check_updates = true` | Документ последнего релиза на `api.github.com`, User-Agent `Bardwave/<version>`, ограничение 8 секунд, лимит 256 KiB. Страница релиза открывается в вашем браузере только по нажатию. |
| Загрузка yt-dlp | Первое использование YouTube, если инструмента нет | Файлы релиза yt-dlp на GitHub |
| Загрузка ffmpeg | Первое использование YouTube в Windows, если инструмента нет | Файлы релиза сборок BtbN FFmpeg на GitHub |
| Аудио с YouTube | Вы добавляете ссылку на YouTube | YouTube, через yt-dlp |

Ещё два момента. Определение адреса не отправляет пакеты. А страница слушателя заставляет браузер игрока (а не Bardwave) запрашивать `cdn.tailwindcss.com`, `code.iconify.design` и `fonts.googleapis.com`. Эти хосты видят IP-адрес игрока. Отправляет ли браузер также адрес страницы, зависит от настройки браузера (не проверено). Страница ведущего загружает только свои собственные файлы.

<a id="https"></a>

### HTTPS

`[server] tls = true` включает HTTPS и `wss://` на том же порту, а ссылки начинаются с `https://`. Без `tls_cert` и `tls_key` Bardwave создаёт самоподписанный сертификат, действующий 397 дней, в папке `tls` каталога данных. При следующем запуске он заменяется, если остаётся меньше 30 дней или если ни один из текущих адресов локальной сети этого компьютера не покрывается. Отпечаток (fingerprint) SHA-256 выводится в консоль и записывается в журнал, поэтому его можно сравнить с предупреждением браузера. **Regenerate certificate** создаёт новый. Изменение применяется при следующем запуске. `tls_cert` и `tls_key` нужно задавать вместе. Сертификат, который не удаётся прочитать, не даёт серверу запуститься и не переключает его на HTTP.

```toml
[server]
tls = true
tls_cert = "/etc/ssl/bardwave/fullchain.pem"   # set both or neither
tls_key = "/etc/ssl/bardwave/privkey.pem"
```

> **Примечание:** Каждый телефон должен доверять самоподписанному сертификату. Это не проверялось на реальном iPhone или телефоне Android. Подробные шаги — в [HTTPS (защищённое соединение)](./https.md).

<a id="not-verified-on-real-hardware"></a>

## Не проверено на реальном оборудовании

Ниже перечислено то, что реализовано и покрыто тестами или сборками CI, но не запускалось на реальных машинах:

- Установщик Windows и пакеты Linux (AppImage, `.deb`).
- `.app` и `.dmg` для macOS, запрос доступа к локальной сети, Gatekeeper, подпись и нотаризация.
- Глобальные горячие клавиши в macOS, Windows и Linux/X11.
- MIDI: только модульные тесты, выключено по умолчанию, не подключено к консоли.
- Названия аудиоустройств, их перечисление и второй аудиопоток (предпрослушивание) в Windows (WASAPI) и Linux (ALSA/JACK). Переключение устройств проверялось только на macOS.
- Выбор каталога данных в каждой ОС.
- HTTPS: только автоматические тесты. Доверие на реальном телефоне не проверялось, с реальной цепочкой Let's Encrypt не пробовали.
- UPnP с реальными роутерами (включая ответы `718` и `725` и случай второго NAT), а также создание правила брандмауэра Windows.
- Предупреждение о VPN с реальными VPN-клиентами и прокси в режиме TUN.
- Правила для прокси и туннелей с реальным туннельным ПО. Проверялись только имитированные заголовки.
- Страница слушателя в iOS Safari и Android Chrome (включая вид без доступа в интернет).
- Проверка обновлений на опубликованном релизе.
- Загрузки yt-dlp и ffmpeg в macOS и Linux, а также загрузка ffmpeg в Windows.
- Поведение при большом числе слушателей одновременно.
- Рекомендации по буферу и обрывам выведены из кода, а не из живых сессий.
- Профили, мастер первого запуска и масштаб интерфейса в Windows и Linux.
