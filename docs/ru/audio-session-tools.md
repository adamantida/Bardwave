# Аудиоустройства, запись, профили и обновления

На этой странице описаны четыре части консоли Bardwave: выбор звуковых карт, запись игровой сессии в WAV, работа с отдельными профилями кампаний и необязательная проверка обновлений. Описание основано на коде в `src/audio`, `src/gui`, `src/profiles.rs`, `src/paths.rs` и `src/updates.rs`. Текст кнопок и надписей приведён в том регистре, который используется в исходном коде. Сама консоль отрисовывает кнопки и подписи блоков заглавными буквами (например, `REC`, `REFRESH DEVICES`, `AUDIO OUTPUT`).

Работа с устройствами написана на основе cpal и проверена только на macOS (CoreAudio). Поведение на Windows (WASAPI) и Linux (ALSA/JACK) не проверено.

<a id="audio-output-devices"></a>
## Устройства вывода звука

Блок **AUDIO OUTPUT** находится на панели сервера, между настройками микса и блоком **Updates**. В нём два выпадающих списка, под каждым есть строка состояния:

| Выпадающий список | Надпись | Назначение |
|---|---|---|
| Основной вывод | `Output` | Устройство, которое воспроизводит микс. Пункт «без выбора» — `System default (<name>)`, либо просто `System default`, если устройство по умолчанию неизвестно. |
| Вывод предпрослушивания (preview) | `Preview` | Устройство, которое воспроизводит предпрослушивания звуков (обычно наушники). Пункт «без выбора» — `Same as output`. |

Изменение применяется сразу. Движок останавливает свои аудиопотоки (streams) и открывает их заново с новым выбором, без перезапуска приложения, а треки продолжают играть. Выбор также сразу сохраняется в `config.toml`.

<a id="choosing-the-output-and-preview-devices"></a>
### Выбор устройств вывода и предпрослушивания

1. Откройте блок **AUDIO OUTPUT**.
2. Откройте выпадающий список `Output` и выберите устройство. Чтобы вернуться к значению по умолчанию, выберите `System default (<name>)`.
3. Откройте выпадающий список `Preview` и выберите наушники. Чтобы воспроизводить предпрослушивания на основном выводе, выберите `Same as output`.
4. Прочитайте строку состояния под каждым выпадающим списком.
5. Нажмите `Refresh devices`, когда подключите или отключите устройство.

Наведите курсор на устройство в списке, чтобы увидеть его сводку, например `2 ch · 44.1 / 48 / 96 kHz · system default`. Сводка строится по наибольшему числу каналов, которое предлагает устройство, и по поддерживаемым частотам из этого списка: 22.05, 44.1, 48, 88.2, 96 и 192 kHz. Длинные имена устройств в выпадающем списке сокращаются многоточием.

Выбор сохраняется в разделе `[audio]`:

```toml
[audio]
output_device = "USB Headphones"   # main output; omit for the system default
preview_device = "Built-in Output" # previews; omit to play them on the main output
```

Правила, которые применяет код:

- Пустое имя (только пробелы) считается незаданным.
- Сначала имена сравниваются точно, затем без учёта регистра и крайних пробелов.
- Если `preview_device` указывает на то же устройство (по имени), что и реально открытый основной вывод, устройство открывается один раз. Тогда предпрослушивания используют основной вывод.
- Предпрослушивания на отдельном устройстве никогда не попадают в аудиопоток игроков. Они также не приглушаются (ducking) и не учитывают фейдеры шин (bus).

> **Примечание:** Имена устройств — это строки, которые возвращает сама система. Имя, сохранённое в одной операционной системе, в другой не существует. В некоторых системах два устройства могут иметь одно имя; выбирается первое.

Устройство, которое указано в настройках, но отсутствует в списке, всё равно показывается в выпадающем списке с суффиксом `(not connected)`. Настройка сохраняется, поэтому достаточно снова подключить устройство и нажать `Refresh devices`.

`Refresh devices` заново читает список устройств в фоновом потоке (пока кнопка показывает `Refreshing...`, консоль не зависает на спящем Bluetooth-устройстве). Когда сканирование заканчивается, Bardwave заново применяет сохранённый выбор, если это может помочь: настроенное устройство есть, но не используется; устройство предпрослушивания, которое не удалось открыть, теперь присутствует; либо вывод завершился с ошибкой или не имеет устройства, хотя устройства есть.

<a id="fallback-and-error-messages"></a>
### Переход на запасной вариант и сообщения об ошибках

Основной вывод открывается в таком порядке:

1. Настроенный `output_device`, если он найден в списке.
2. Системное устройство по умолчанию.

Если указанное устройство отсутствует, движок использует системное устройство по умолчанию и сообщает об этом. Если указанное устройство найдено, но открыть его не удаётся, движок тоже пробует системное устройство по умолчанию. Строка состояния показывает причину в скобках, например:

```text
Active: Built-in Output - 48000 Hz, 2 ch (output device "Bluetooth Speaker" not found; using the system default)
```

```text
Active: Built-in Output - 48000 Hz, 2 ch (could not open "USB Headphones" (<error>); using the system default)
```

Если ни одно устройство открыть не удаётся (нет устройства по умолчанию или не получается создать либо запустить поток), движок продолжает работу без звуковой карты, в режиме без окна (headless). Слушатели по-прежнему получают аудиопоток, но на компьютере ничего не звучит. Строка состояния тогда показывает `Error: no output device opened (network only)`, а за ней причину в скобках, например `(local output unavailable: <error>)`.

Если открытый поток даёт сбой во время работы (например, устройство отключили), основной вывод переходит в состояние `Error: <message>`. Самостоятельно он не восстанавливается. Подключите устройство и нажмите `Refresh devices` или выберите устройство заново.

Строки состояния:

| Строка состояния | Значение |
|---|---|
| `Active: <device> - <rate> Hz, <ch> ch` | Вывод работает. Причина в скобках добавляется, когда использовался запасной вариант или преобразование формата. |
| `Output not started` | Вывод ещё не открывался. |
| `Error: no output device opened (network only)` | Звуковая карта не открылась. Сервер по-прежнему передаёт аудиопоток слушателям. |
| `Error: <message>` | Вывод завершился с ошибкой. Сообщение и есть причина. |
| `Previews play on the main output` | Отдельное устройство предпрослушивания не используется. |
| `Active: <device> - <rate> Hz, <ch> ch` (под `Preview`) | Предпрослушивания играют на своём устройстве. |
| `Error: preview device "<name>" not found; previews play on the main output` | Настроенное устройство предпрослушивания отсутствует. Предпрослушивания переходят на основной вывод. |
| `Error: could not open the preview device: <error>; previews play on the main output` | Устройство предпрослушивания есть, но открыть его не удаётся. Переход на основной вывод такой же. |
| `Error: could not start the preview stream: <error>; previews play on the main output` | Поток предпрослушивания создан, но не запустился. Переход на основной вывод такой же. |
| `Error: <error>; previews play on the main output` | Поток предпрослушивания завершился с ошибкой во время работы (например, наушники отключили). Предпрослушивания возвращаются на основной вывод. |

Устройство предпрослушивания пробуется даже тогда, когда у основного вывода нет устройства (режим без окна).

Другие сообщения, которые вы можете увидеть:

| Сообщение | Где | Значение |
|---|---|---|
| `<name> (not connected)` | Пункт выпадающего списка | Настроенного устройства нет в списке. |
| `Error: ...` под блоком | Раздел аудио | Сканирование устройств не удалось (например, `could not list output devices: ...`), или не удалось применить изменение устройства (например, `the audio engine is not running`). |
| `Refreshing...` | Кнопка | Выполняется сканирование устройств. |

<a id="buffer-size-sample-rate-and-channels"></a>
### Размер буфера, частота дискретизации и каналы

Эти три параметра не входят в выпадающие списки. Блок только показывает их в строке вида `buffer: 960 frames (20.0 ms) - 48000 Hz - 2 ch`. При `buffer_size = 0` строка начинается с `buffer: driver default`.

| Параметр | По умолчанию | Допустимые значения | Примечания |
|---|---|---|---|
| `sample_rate` | `48000` | от `8000` до `192000` | Значения вне диапазона записываются в журнал и заменяются на `48000`. |
| `channels` | `2` | от `1` до `8` | Значения вне диапазона записываются в журнал и заменяются на `2`. `1` сводит звук в моно. При числе каналов больше 2 дополнительные каналы получают сведение левого и правого каналов в моно. |
| `buffer_size` | `960` | `0` или от `64` до `8192` | Кадры на буфер устройства. `0` оставляет выбор драйверу. Значения вне диапазона записываются в журнал и заменяются на `480` (10 ms при 48 kHz), а не на `960`. |

```toml
[audio]
sample_rate = 48000
channels = 2
buffer_size = 960   # 20 ms at 48 kHz
```

Эти параметры определяют только то, как открывается звуковая карта компьютера. Микс, сетевой аудиопоток и запись игровой сессии всегда имеют формат 48 kHz стерео.

Значения читаются при запуске приложения. Смена устройства или последующее изменение `config.toml` их не перечитывает. Информационная строка под выпадающими списками показывает значения из конфигурации в том виде, в каком они записаны, даже если значение вне диапазона было заменено.

Движок пытается открыть устройство в таком порядке:

1. Настроенные частота и число каналов в 32-битном float.
2. Формат микса: 48 kHz стерео, 32-битный float.
3. Стерео 32-битный float на другой частоте (частота устройства по умолчанию, если она подходит, иначе ближайшая к 48 kHz), с передискретизацией в аудио-колбэке (функции обратного вызова).
4. Собственный формат устройства по умолчанию (любые частота, число каналов и формат выборок), с передискретизацией и преобразованием.

Если устройство не может работать с настроенными частотой и каналами или микс нужно преобразовать, строка состояния показывает причину, например `device has no 48 kHz stereo f32 mode; using 44100 Hz stereo f32 and resampling`. Если устройство не принимает фиксированный `buffer_size`, движок повторяет попытку с размером буфера устройства по умолчанию (в консоли сообщения нет, оно записывается в журнал).

> **Примечание:** Комментарии в исходном коде движка всё ещё упоминают буфер по умолчанию 10 ms. Настроенное по умолчанию значение — `960` кадров, то есть 20 ms при 48 kHz. Значение 10 ms (`480` кадров) используется только как запасное для некорректного `buffer_size`.

<a id="session-recording"></a>
## Запись игровой сессии

Кнопка **Rec** на верхней панели записывает игровую сессию в файл WAV. Кнопка **folder** рядом с ней выбирает папку записей.

| Элемент | Надпись или подсказка | Поведение |
|---|---|---|
| Кнопка REC, без записи | `Rec` (подсказка: `Record the mix the players hear to a WAV file`) | Запускает запись. |
| Кнопка REC, идёт запись | `Stop rec`, или `Stop`, когда панель узкая (подсказка: `Stop and save the recording`) | Останавливает запись и сохраняет файл. |
| Кнопка folder | Подсказка: `Recordings folder: <path>`, далее `Click to change (applies to the next recording)` | Открывает выбор папки с заголовком `Recordings folder`. Нажатие во время записи ничего не делает. При узком окне верхняя панель первой скрывает эту кнопку. |
| Индикатор | `HH:MM:SS  ·  <size>` | Прошедшее время и размер на диске (все части, включая заголовки) во время записи. Показывается, когда на панели достаточно места. |
| `<n> lost` | Текст янтарного цвета | Кадры были отброшены, потому что диск не успевал за записью. |

Кнопка REC неактивна, пока запись запускается или пока завершается предыдущая. Запуск и остановка выполняются в коротких фоновых потоках, поэтому консоль остаётся отзывчивой. Файл завершает фоновый поток записи после `Stop rec`. Затем консоль показывает `Saved <file name> (<duration>, <size>)`, а если запись разбита на части, — ` in <n> files`, а если кадры были потеряны, — `; <n> frames were lost (disk too slow)`. Размер показывается в единицах по основанию 1024 (`KB`, `MB`, `GB`).

<a id="what-is-recorded"></a>
### Что записывается

Запись — это микс, который слышат игроки:

- Он берётся после общей громкости микшера и лимитера, в точке, где микс передаётся сетевому модулю трансляции (broadcaster).
- Он имеет формат 48 kHz стерео независимо от частоты звуковой карты и не зависит от того, какое устройство воспроизводит звук.
- Предпрослушивания звуков в нём нет. Предпрослушивания идут по своему пути и никогда не попадают в аудиопоток игроков.
- Запись никогда не блокируется аудио-колбэком. Если поток записи отстаёт из-за медленного диска, целые буферы отбрасываются и учитываются как потерянные кадры.
- Когда ничего не воспроизводится, поток записи дополняет тишину по системным часам. Файл сохраняет реальное время сессии.

Работа записи, когда сервер остановлен и никто не подключён, на реальной сессии не тестировалась (не проверено). Модуль записи подключается к выходу микшера до запуска сервера.

<a id="where-files-go-and-how-they-are-named"></a>
### Где сохраняются файлы и как они называются

По умолчанию папка — `recordings/` внутри каталога данных запущенного профиля. Каталог данных описан в разделе [Профили](#profiles). Для профиля по умолчанию это корневой каталог данных.

Файлы называются по времени UTC, в которое начинается запись:

```text
bardwave-20261119-203015.wav
```

- Если имя занято, добавляются `-2`, `-3` и так далее (до `-999`). Запись никогда не перезаписывается.
- Запись, для которой нужно больше одного файла, продолжается в файлах `bardwave-20261119-203015_part2.wav`, `_part3.wav` и так далее. После переименования с `-2` части следуют за ним, например `bardwave-20261119-203015-2_part2.wav`.

Чтобы изменить папку, нажмите кнопку **folder**. Выбранная папка сохраняется в `[gui] recordings_dir` в конфигурации запущенного профиля. Она применяется к следующей записи. Пустое значение считается незаданным. Если папка отсутствует, она создаётся.

```toml
[gui]
recordings_dir = "/Users/you/Recordings"
```

<a id="size-limits-and-splitting"></a>
### Ограничения размера и разбиение на части

| Настройка | Значение | Действие |
|---|---|---|
| Размер части | `1800000000` байт (около 1.8 GB) аудиоданных в файле | Запись продолжается в следующем файле `_partN.wav`. |
| Предупреждение о размере | Больше `1500000000` байт (около 1.5 GB) в одном файле | Показывает `Large recording: <x> GB in this file; it continues in a new file at <y> GB`. |
| Минимум свободного места | 200 MB (`200 * 1024 * 1024` байт) | Запись не начинается при меньшем объёме. |
| Предупреждение о нехватке места | Меньше часа свободного места при текущем формате, проверяется при запуске записи | Показывает `Low disk space: <n> MB free, about <n> min of recording`. |
| Обновление заголовка | Около одного раза в секунду | Файл, оставшийся после сбоя, является корректным WAV до последнего обновления. |

Проверка свободного места работает в Unix-системах (macOS, Linux). В других системах (Windows) проверка пропускается, и при заполненном диске запись завершается ошибкой записи (не проверено на Windows).

Формат WAV не может превышать 4 GB на файл, поэтому размер части ограничен чуть ниже этого значения (около 4.29 GB). Размер части по умолчанию значительно меньше ограничения.

Примерные размеры файлов, рассчитанные для 48 kHz стерео:

| Формат | В час | Частей в час |
|---|---|---|
| 16-битный PCM (по умолчанию) | около 691 MB | меньше одной части |
| 32-битный float | около 1.38 GB | около 0.8 части |

<a id="recording-settings"></a>
### Настройки записи

Формат задаётся в `config.toml`. В консоли для него нет элемента управления.

```toml
[gui]
record_float32 = false   # false: 16-bit PCM (default); true: 32-bit float
```

<a id="recording-troubleshooting"></a>
### Устранение неполадок записи

| Симптом | Причина | Что делать |
|---|---|---|
| `Cannot start recording: not enough free disk space: <n> MB free, at least 200 MB needed` | Слишком мало свободного места. | Освободите место или выберите другую папку. |
| `Cannot start recording: cannot create the recordings folder <path>: ...` | Папку не удаётся создать. | Выберите кнопкой **folder** папку, в которую можно писать. |
| `Cannot start recording: cannot create <path>: ...` | Не удаётся создать первый файл. | Проверьте, что в папку можно записывать. |
| `Cannot start recording: a recording is already in progress` | Запись уже идёт. | Сначала остановите её. |
| `Low disk space: ...` | Меньше часа свободного места. | Освободите место или скоро остановите запись. |
| `<n> lost` янтарным цветом или `frames were lost (disk too slow)` | Диск не успевает за записью. | Записывайте на более быстрый диск. |
| `Recording stopped: ...` | Произошла ошибка записи. | Проверьте диск и сообщение. Файл до этого момента сохраняется. |

<a id="profiles"></a>
## Профили

Профиль — это отдельная кампания со своими `config.toml` и библиотекой. Профиль по умолчанию — это корневой каталог данных. Именованный профиль хранится в собственной папке:

```text
<root>/                       default profile: config.toml, bardwave-library/
<root>/profiles/<name>/       named profile: config.toml, bardwave-library/
<root>/recent.toml            shared: recently used profiles
<root>/bardwave.log           shared: log (written when [logging] file_logging = true)
<root>/tools/                 shared: downloaded tools
```

Корневой каталог определяется правилами платформы в `src/paths.rs`. Коротко: это папка исполняемого файла, если в ней уже есть `config.toml` или файл `portable.flag`, либо если в неё можно писать (и она не находится внутри приложения macOS в формате `.app`). Иначе это `~/Library/Application Support/Bardwave` в macOS, `%APPDATA%\Bardwave` в Windows и `$XDG_DATA_HOME/bardwave` (или `~/.local/share/bardwave`) в Linux. Конфигурация, библиотека и записи относятся к каждому профилю. Журнал, инструменты и `recent.toml` общие для всех профилей.

<a id="starting-with-a-profile"></a>
### Запуск с профилем

Запустите Bardwave с параметром `--profile`:

```bash
soundshared --profile "Campaign A"
soundshared --profile=Campaign-A
soundshared --profile default
```

Исполняемый файл называется `soundshared`, когда вы собираете его через cargo (например, `cargo run --release -- --profile "Campaign A"`); пакет Linux `.deb` устанавливает его как `bardwave`. `--profile default` — то же самое, что и без параметра. Параметр также работает вместе с `--server-only`.

Правила для имени:

| Правило | Пример отклонённого имени |
|---|---|
| от 1 до 32 символов (крайние пробелы убираются) | пустое имя или имя из 33 символов |
| Буквы, цифры, пробелы, `-` и `_` (буквы любого алфавита) | `Campaign/A`, `camp.a` |
| Не `default` (в любом регистре) | `Default` |
| Не зарезервированное имя Windows | `CON`, `PRN`, `AUX`, `NUL`, от `COM1` до `COM9`, от `LPT1` до `LPT9` |
| Уникальное, без учёта регистра | `campaign a`, если существует `Campaign A` |

Если имя некорректно, Bardwave не запускается. Он выводит `Error: invalid profile name: ...` в stderr и завершается с кодом 2. Если не используется `--server-only`, также показывается окно сообщения. `--profile` без значения даёт `--profile needs a profile name`. Тот же код выхода 2 используется, когда не удаётся создать папку профиля. Если параметр повторяется, действует последний.

Профиль, которого ещё нет, создаётся через `--profile` (его папка создаётся при запуске). При первом запуске он использует настройки по умолчанию.

<a id="switching-profiles"></a>
### Переключение профилей

Откройте имя профиля на верхней панели (перед ним отображается подпись `PROFILE`, если на панели есть место). Заголовок окна именованного профиля заканчивается на ` — <name>`. В меню есть заголовок `Switch to (restarts Bardwave)`.

1. Выберите профиль из списка. Профиль по умолчанию отображается как `Default`. Запущенный профиль отмечен `(running)` и не может быть выбран.
2. В диалоге **Switch Profile** прочитайте текст: `Switch to "<name>"? The server and all sounds stop, the current profile is saved.`
3. Нажмите `Switch` (или `Cancel`).

Bardwave сохраняет текущий профиль, закрывает окно, останавливает сервер и звук, а затем запускает новый процесс с `--profile <name>` (`--profile default` для профиля по умолчанию). Новый процесс отсоединяется. Если его не удаётся запустить, ошибка записывается в журнал, и Bardwave просто завершается. Переключение есть только в окне консоли; у `--server-only` меню нет.

<a id="managing-profiles"></a>
### Управление профилями

В меню профиля есть такие пункты:

| Пункт | Результат |
|---|---|
| `New profile…` | Открывает **New Profile**. |
| `Manage profiles…` | Открывает **Profiles** с кнопками `Rename` и `Delete` для каждого другого профиля. У профиля по умолчанию и у запущенного профиля кнопок нет. В диалоге также есть `New profile…` и `Close`. |
| `Open data folder` | Открывает каталог данных запущенного профиля в файловом менеджере. |

В **New Profile** есть поле `Profile name` (подсказка в поле `Campaign name`), флажок `Copy the current library` и кнопка `Create`. Под полем показывается `Letters, digits, space, - and _` или причина, по которой имя отклонено. Флажок копирования:

- копирует `config.toml` и `bardwave-library/` запущенного профиля (больше ничего, поэтому записи не копируются; символические ссылки пропускаются);
- копирует всю конфигурацию, поэтому другие настройки, например порт сервера, тоже копируются;
- переписывает пути библиотеки в скопированной конфигурации, чтобы они указывали на новую папку;
- выполняется в фоне, а в диалоге показывается `Copying the library…`. Диалог нельзя закрыть до окончания копирования.

Частично скопированный профиль удаляется, если копирование не удалось. Без параметра копирования создаётся пустая папка. После `Create` открывается диалог **Switch Profile** с сообщением `Profile created`. Новый профиль не запускается, пока вы не нажмёте `Switch`.

**Rename Profile** переименовывает папку, принимает новое имя по тем же правилам (поле называется `New name`) и меняет пути библиотеки в его конфигурации. Кнопка называется `Rename`. Можно изменить только регистр букв. После переименования в списке показывается `Renamed <old> to <new>`.

**Delete Profile** окончательно удаляет папку профиля. Корзины нет.

- Пустой профиль (папка без файлов) удаляется без вопросов. Диалог сообщает `This profile is empty.`
- Для непустого профиля нужно ввести его точное имя в поле `Type "<name>" to confirm`. Диалог сообщает `Its config and library are deleted for good. There is no trash.` Кнопка остаётся неактивной, пока имя не совпадёт (с учётом регистра).
- Кнопка называется `Delete`. После удаления в списке показывается `Deleted <name>`.

> **Предупреждение:** Удаление профиля стирает всю его папку: конфигурацию, библиотеку и папку `recordings/` по умолчанию. Это нельзя отменить. Если нужна резервная копия, сначала используйте `Open data folder` и скопируйте папку.

Запущенный профиль нельзя переименовать или удалить. Консоль не предлагает эти кнопки, а код отказывает с сообщением `The running profile cannot be changed`. Сначала переключитесь на другой профиль.

<a id="recent-profiles"></a>
### Недавние профили

`recent.toml` в корневом каталоге данных хранит до 8 имён профилей, сначала самые новые. Каждый запуск Bardwave (включая `--server-only`) перемещает запущенный профиль в начало списка.

- В меню профилей сначала идут недавние профили, затем `Default`, если его нет среди них, а потом остальные профили по алфавиту.
- Профиль, которого больше нет, не показывается.
- Переименование или удаление профиля убирает его прежнее имя из списка недавних.
- Отсутствующий или нечитаемый `recent.toml` считается пустым списком.

```toml
# <root>/recent.toml
recent = ["Campaign A", "default"]
```

Профиль по умолчанию хранится как `default`.

<a id="update-check"></a>
## Проверка обновлений

Проверка ищет более новый релиз. Она ничего не загружает и ничего не устанавливает. Находится она в блоке **Updates** на панели сервера.

| Элемент | Надпись или текст | Поведение |
|---|---|---|
| Кнопка | `Check for updates` (подсказка: `Asks GitHub for the newest release. Nothing else is sent or downloaded.`) | Запускает одну проверку сейчас. Неактивна, пока выполняется проверка. |
| Флажок | `Check once a day at start` (подсказка: `Off by default: Bardwave makes no network requests on its own.`) | Включает автоматическую проверку. |
| Строка результата | `Checking...`, `Up to date (v<version>)`, `Update available: v<version>` | Показывает результат. |
| Ссылка | `Open release page` | Открывает страницу релиза в браузере. Показывается, когда доступно обновление. |

Когда доступно обновление, строка состояния также показывает ссылку `Update available: v<version>`, которая открывает ту же страницу.

Ошибки показываются янтарным цветом:

| Сообщение | Причина |
|---|---|
| `Network error: could not reach the update server` | Нет соединения, сбой DNS или TLS либо превышено время ожидания в 8 секунд. |
| `Update server answered HTTP <code>` | Сервер ответил кодом ошибки (например, ограничением частоты запросов). |
| `Update server sent an oversized reply` | Ответ был больше 256 KiB. |
| `Update server sent an unreadable reply` | Ответ не был документом релиза. |
| `Could not start the update check` | Не удалось запустить фоновый поток. |

Проверка по умолчанию выключена:

```toml
[gui]
check_updates = false      # daily check at start; default false
last_update_check = 0      # unix time of the last check; written by Bardwave
```

Если `check_updates` включён, Bardwave проверяет при каждом запуске консоли, если ещё ни разу не проверял, или если с `last_update_check` прошло не меньше 24 часов (если системные часы ушли назад, проверка тоже считается нужной). Ручная проверка тоже обновляет `last_update_check`. Кнопка ручной проверки работает независимо от того, включена ли ежедневная проверка. Предлагаются только стабильные релизы: черновики и предварительные выпуски игнорируются, а сборке, версия которой не разбирается как `major.minor.patch`, никогда не сообщается об обновлении.

Отправляется один запрос `GET` к API GitHub «latest release» (`https://api.github.com/repos/adamantida/Bardwave/releases/latest`). Код задаёт только два заголовка:

| Заголовок | Значение |
|---|---|
| `User-Agent` | `Bardwave/<version>` |
| `Accept` | `application/vnd.github+json` |

Запрос не несёт cookie, авторизации и referrer. HTTP-библиотека добавляет собственные транспортные заголовки (например, `Host`), а GitHub видит IP-адрес, с которого отправлен запрос, как и в любом веб-запросе. Время ожидания запроса — 8 секунд. Ответ больше 256 KiB отклоняется. Проверка не отправляет настройки, содержимое библиотеки или имена профилей. Ссылка на страницу релиза строится Bardwave по номеру версии и никогда не берётся из ответа.

> **Примечание:** Запрос и разбор ответа проверены на локальном тестовом сервере. Реальный запрос к GitHub из релизной сборки — не проверено в этом документе.
