# Сеть, игроки и удалённая панель ведущего

Bardwave транслирует вывод консоли слушателям по локальной сети или через интернет. На этой странице описано, как запускается и становится доступен сервер, как игроки подключаются с помощью ключа доступа, что показывает страница слушателя и как ведущий (game master, GM) управляет консолью с другого устройства через удалённую панель. Настройка HTTPS описана в [HTTPS (защищённое соединение)](./https.md). Связанные страницы: [Начало работы](./getting-started.md), [Справочник по конфигурации](./configuration.md), [Устранение неполадок, FAQ и безопасность](./troubleshooting-security.md).

Здесь задействованы два секрета. **Ключ доступа** позволяет игрокам слушать. **Токен ведущего** позволяет управлять консолью. Ключ доступа никогда не открывает панель ведущего.

## Запуск и остановка сервера

Сервер не запускается вместе с приложением. Ведущий запускает сервер с панели **Network Server** (сетевой сервер), которая находится в правой колонке консоли и имеет заголовок `02 / Network`. В режиме `--server-only` окна нет, и сервер запускается сам, см. [Страница /control без окна](#headless-control-page).

1. Проверьте **Port** (порт) и **Bind Address** (адрес привязки) в блоке **Configuration** (конфигурация) внизу панели, пока сервер остановлен.
2. Нажмите **Start Server** (запуск сервера).
3. Нажмите **Copy Link** (копировать ссылку) или значок копирования рядом с **Listen URL** (ссылка для прослушивания) и отправьте ссылку игрокам.
4. Нажмите **Stop Server** (остановка сервера), чтобы снять трансляцию с эфира.

Карточка статуса показывает состояние заглавными буквами:

| Состояние | Значение |
| --- | --- |
| `Live` | Работает. Ниже: `Broadcasting to N listeners`. |
| `Starting` | `Binding the listen socket`. Кнопка неактивна. |
| `Error` | Последний запуск не удался. Причина показана в сокращённом до 34 символов виде. Полный текст попадает в журнал. Кнопка превращается в **Retry Server** (повторить запуск сервера). |
| `Off Air` | Остановлен. Ниже: `Server stopped`. |

В блоке **Listeners** (слушатели) показаны текущее число слушателей и `Peak` — наибольшее число с момента запуска сервера.

Поле **Port** принимает значения от 1 до 65535. Порт `0` отклоняется (`Port must be 1–65535`). Поле **Bind Address** принимает числовой IP-адрес (IPv4 или IPv6), а не имя хоста (`Bind must be an IP address`). Некорректный ввод не меняет последнее правильное значение, а ошибка показывается под полями. Правильное изменение применяется сразу и сохраняется в `config.toml` (появляется отметка `Saved`). Оба поля можно редактировать только при остановленном сервере; подсказка под ними показывает `Editable while stopped` или `Stop the server to edit`.

Остановка сервера отключает всех слушателей и все удалённые сессии ведущего, снимает проброс порта на роутере и очищает сообщения о VPN и брандмауэре. Открытые страницы слушателей продолжают повторять попытки и снова подключаются после нового запуска сервера.

<a id="lan-or-internet"></a>

## Локальная сеть или интернет

Публикуемый адрес зависит от адреса привязки:

| Адрес привязки | Публикуемый адрес |
| --- | --- |
| `0.0.0.0` или `::` (по умолчанию `0.0.0.0`) | Обнаруженный адрес локальной сети (LAN) того же семейства, что и адрес привязки. Если такой адрес не найден, петлевой адрес (loopback): `127.0.0.1` или `[::1]`. |
| Петлевой адрес (`127.0.0.1`, `::1`) | Только петлевой адрес. Подключиться может только этот компьютер. |
| Любой другой IP-адрес | Этот адрес, как он введён. |

Если адрес обнаружен, частные адреса локальной сети имеют приоритет над публичными. Среди IPv4-адресов локальной сети предпочтение отдаётся `192.168.x.x`, затем `10.x.x.x`, затем `172.16.0.0/12` (там обычно находятся Docker, WSL и многие адаптеры VPN). Адреса тестового диапазона (`198.18.0.0/15`, которые используют некоторые адаптеры VPN и прокси), адреса link-local, петлевой адрес и другие непригодные диапазоны не выбираются никогда. Адреса CGNAT (NAT провайдера), например адреса Tailscale (`100.64.0.0/10`), используются в последнюю очередь, перед петлевым адресом.

Игроки в той же сети используют ссылку локальной сети. Игрокам из других сетей нужна ссылка **Internet** (интернет). Она появляется, только если роутер пробрасывает порт, см. [Проброс порта через UPnP](#upnp-port-forwarding).

В блоке **Listen URL** показаны публикуемая ссылка вместе с ключом доступа (на экране ключ сокращён до 30 символов). Если публикуемый адрес не является петлевым, под ней выводится строка `Local` со ссылкой для этого компьютера через петлевой адрес. Нажмите на неё, чтобы скопировать эту ссылку вместе с ключом доступа.

> **Предупреждение:** Ключ доступа передаётся в адресе ссылки. Прежде чем отправлять игрокам ссылку через интернет, включите [HTTPS](#https).

<a id="upnp-port-forwarding"></a>

## Проброс порта через UPnP

При `upnp = true` (значение по умолчанию) сервер просит роутер пробросить порт прослушивания (TCP, UPnP IGD). Запрос выполняется в фоне и никогда не задерживает запуск. Ссылка для локальной сети появляется сразу, а строка для интернета добавляется, только если роутер предоставляет проброс. Поиск отправляется с каждого частного IPv4-адреса компьютера, поэтому он работает и тогда, когда VPN забирает маршрут по умолчанию (не проверено на реальных роутерах).

| Строка в блоке Listen URL | Значение |
| --- | --- |
| `Internet: asking the router…` | Идёт запрос к роутеру. |
| `Internet http://<public-address>:<port>` | Проброс на публичный адрес (`https://`, если HTTPS включён). Нажмите, чтобы скопировать ссылку вместе с ключом доступа. Внешний порт может отличаться от локального, если другой компьютер за роутером уже пробрасывает этот порт. |
| `Internet: blocked by a second NAT (<address>)` | Внешний адрес роутера — частный. |
| `Internet: no UPnP router` | Ни один роутер не ответил или ни один не выделил проброс. Наведите курсор на строку, чтобы увидеть последнюю причину. Сервер повторяет попытку каждые 30 секунд. |

Если строки `Internet` нет вообще, проброс порта выключен или не применяется (см. пункт «Привязка к петлевому или IPv6-адресу» ниже).

Оговорки:

- **Второй NAT.** Из-за CGNAT или модема провайдера перед роутером внешний адрес становится частным. Попросите провайдера выдать публичный IP-адрес или пробросьте порт на вышестоящем устройстве.
- **VPN.** Когда VPN с полным туннелированием забирает маршрут по умолчанию, роутер всё равно пересылает соединение, но ответ уходит через туннель. Тогда панель показывает `VPN active (<address>): internet players can't connect until it is off`. Выключите VPN или исключите из него Bardwave. Предупреждение выводится, когда адрес маршрута по умолчанию отличается от публикуемого IPv4-адреса локальной сети.
- **Брандмауэр.** В Windows сервер пытается добавить входящее разрешающее правило для порта (`netsh`, все сетевые профили), для этого нужны права администратора. Если это не удаётся, панель показывает `Firewall: port <port> not opened - allow Bardwave for public networks or run as admin`. Windows часто помечает сети как Public (общедоступные), поэтому разрешите Bardwave и там. В других системах Bardwave брандмауэр не трогает; если он включён, откройте порт самостоятельно (не проверено).
- **Срок аренды (lease).** Bardwave запрашивает аренду на два часа и продлевает её на середине срока. Если роутер требует постоянных пробросов, проверка повторяется каждые 30 минут. **Stop Server** убирает проброс.
- **Привязка к петлевому или IPv6-адресу.** Проброс порта пропускается: роутеры пробрасывают только IPv4, а сокет на петлевом адресе недоступен извне. При конкретном IPv4-адресе привязки проброс указывает только на этот адрес.
- **Проверка.** Роутеры без поддержки NAT loopback могут не пускать по ссылке для интернета изнутри вашей сети. Проверяйте её через мобильный интернет.
- **Выключение.** Установите `upnp = false` в `config.toml` и перезапустите приложение.

> **Примечание:** Если UPnP не работает, проброс порта вручную на роутере тоже подходит, но этот вариант здесь не описан (не проверено).

<a id="player-link-and-access-key"></a>

## Ссылка для игроков и ключ доступа

Ссылка для игроков имеет такой вид (`https://`, если HTTPS включён):

```text
http://<advertised-address>:<port>/?k=<access-key>
```

Ключ доступа берётся из `[server] access_token` в `config.toml`:

- Ключ создаётся и сохраняется при первом запуске, если в конфигурации его нет.
- `access_token = ""` (или только пробелы) отключает проверку. Панель тогда показывает `ACCESS KEY OFF - ANYONE CAN LISTEN`, в ссылке нет `?k=`, а журнал предупреждает, что поток открыт.
- Созданные ключи состоят из 16 символов: строчных букв и цифр. Ключи чувствительны к регистру.
- Панель показывает `ACCESS KEY` и первые символы ключа. Значок обновления рядом с ним сразу выдаёт новый ключ без вопроса с подтверждением (он также включает ключ обратно, если поле было пустым). Подсказка при наведении предупреждает, что текущая ссылка перестаёт работать сразу и все слушатели отключаются. Затем отправьте новую ссылку. Новый ключ сохраняется в `config.toml`.

Ключ защищает WebSocket аудиопотока (`/ws/audio`) и API статуса (`/api/status`). Страница слушателя и её статические файлы (скрипты, значки, манифест) общедоступны.

<a id="listener-page"></a>

## Страница слушателя

Игроки открывают ссылку в браузере. Заголовок страницы: `Bardwave Listener`. Страница воспроизводит тот же микс, что и консоль, и на стороне игрока ничего не устанавливается.

Страница начинается с анимации загрузки продолжительностью от 6 до 10 секунд (около 0.3 s, если устройство запрашивает уменьшенное движение). Прослушивание никогда не начинается само: игрок должен нажать кнопку подключения.

> **Примечание:** Страница загружает Tailwind CSS, компонент Iconify и шрифт JetBrains Mono из публичных CDN (`cdn.tailwindcss.com`, `code.iconify.design`, `fonts.googleapis.com`). Устройство без доступа в интернет может показать сломанную страницу или страницу без стилей; как она выглядит в локальной сети без интернета, не проверялось (не проверено).

### Подключение

Кнопка подключения меняет надпись в зависимости от состояния:

| Текст кнопки | Когда |
| --- | --- |
| `Establish Link` | Нет подключения. Нажмите, чтобы подключиться. |
| `Linking...` | Подключение. Кнопка неактивна. |
| `Stop Retrying` | Ожидание переподключения. Нажмите, чтобы остановить. |
| `Terminate Link` | Подключено. Нажмите, чтобы отключиться. |

Строка состояния показывает `Node Offline`, `Linking...`, `Reconnecting #<n>`, `Node Online`, `Access Denied` или `Link Error` (а также `Audio Error`, когда браузер отказывается запускать звук).

Перед открытием потока страница запрашивает `/api/status` с ключом. Если сервер отклоняет ключ, страница показывает `Access Denied`, прекращает повторные попытки и объясняет: после смены ключа — `This link is no longer valid: the GM issued a new access key. Ask for the current link.`, а для ссылки без ключа — `This link has no access key. Open the full link from the GM (it ends with ?k=...).`

### Переподключение

После обрыва страница повторяет попытки с задержкой 1 s, 2 s, 4 s, 8 s, затем 15 s. Каждая задержка случайным образом уменьшается до 30 %. Нарастающая задержка сбрасывается, только если соединение продержалось 10 s. Рукопожатие, которое длится дольше 10 s, прерывается, а соединение, молчащее 30 s, разрывается (страница отправляет ping каждые 10 s). Попытки не ограничены. Когда вкладка снова становится видимой или браузер сообщает, что сеть появилась, страница повторяет попытку сразу, не дожидаясь окончания задержки. Когда ведущий останавливает сервер, страницы показывают `Reconnecting #<n>`, пока сервер не будет запущен снова.

### Личная громкость

**My_Volume** (личная громкость) задаёт громкость этого устройства от 0 % до 100 %. Это не меняет микс ведущего и звук у других игроков. Нажмите кнопку с процентами, чтобы выключить и включить звук; при выключении она показывает `MUTED`. Ползунок отражает воспринимаемую громкость: усиление равно квадрату процентного значения. Настройка сохраняется в браузере (`localStorage`, ключ `bardwave.volume`), поэтому действует только в этом браузере. Уровни шин (bus) нельзя изменить для каждого игрока отдельно, потому что все получают один общий микс.

### Качество связи

Панель **[ LINK_QUALITY ]** (качество связи) показывает **Quality** (качество), **Latency (est.)** (задержка, оценка), **Buffer** (буфер), **Packet loss (10 s)** (потеря пакетов за 10 s) и **Screen stay-awake** (запрет засыпания экрана). Пока идёт звук, **Quality** принимает значения `GOOD`, `FAIR` или `WEAK`, в остальных случаях — `IDLE`, `WAITING`, `RECONNECTING` или `OFFLINE`. Потеря пакетов считается за последние 10 секунд и показывает `--`, пока не получено хотя бы 50 пакетов.

`FAIR` появляется при потере 0.5 % или выше, джиттере прихода 30 ms или выше либо при любом опустошении буфера (underrun) за окно измерения. `WEAK` требует устойчивых проблем, а не одного всплеска: потеря 2 % и выше, растянутая не меньше чем на 3 секунды, джиттер 80 ms и выше либо 3 и более опустошения буфера за окно измерения, при 3 оценках подряд (по одной в секунду). Сбрасывается после 5 чистых оценок. Тогда страница показывает: `Weak network: audio may stutter or drop out. Move closer to the router or switch to a better connection.` Также страница показывает индикаторы уровня в реальном времени, отображение буфера и счётчики underruns, overruns и потерянных кадров.

### Сейчас играет

Когда ведущий запускает сцену или музыкальный трек, строка **Now_Playing** (сейчас играет) показывает название сцены, а под ней — название трека. Когда ничего не играет, строка скрыта. Тот же текст передаётся в элементы управления медиа на экране блокировки телефона.

### Запрет засыпания экрана, экран блокировки и PWA

Во время прослушивания страница запрашивает у браузера запрет засыпания экрана (Wake Lock). **Screen stay-awake** показывает `ON`, `PAUSED` (браузер снял запрет), `BLOCKED` (отказано, например режимом экономии батареи), `N/A (needs https)` на обычном `http://`, `N/A`, если браузер не поддерживает такой API, и `OFF` или `--`, когда прослушивания нет. Браузер снимает запрет, когда вкладка скрыта, а страница снова запрашивает его, когда вкладка возвращается. Поведение телефонов и планшетов не проверялось (не проверено).

Страница регистрирует элементы управления медиа на экране блокировки (Media Session), в качестве заголовка используются сцена и трек. Живой поток нельзя поставить на паузу на месте: пауза или остановка на экране блокировки отключает соединение, а воспроизведение подключает его снова. Чтобы виджет появился, страница проигрывает беззвучный зацикленный звук; он не содержит звука.

Страницу можно установить как PWA (приложение на домашнем экране) с именем `Bardwave Listener`, отображением standalone и портретной ориентацией. Страница запрашивает манифест с тем же ключом `?k=`, а манифест вставляет его в стартовый URL, поэтому значок на домашнем экране открывается с ключом. В манифест попадают только ключи из букв, цифр, `-` и `_` длиной до 64 символов; ключ, созданный вручную, с другими символами открывает значок без ключа, и игрок получает `Access Denied`. Сервис-воркера (service worker) нет, поэтому страница не работает офлайн. Для установки может понадобиться безопасный контекст, см. [HTTPS (защищённое соединение)](./https.md) (не проверено).

<a id="gm-remote-panel"></a>

## Удалённая панель ведущего

Панель ведущего — это страница `/control` (заголовок вкладки на телефоне: `Bardwave GM`). Она позволяет ведущему управлять консолью с телефона или другого компьютера, пока сервер работает. Её отдаёт окно консоли, а также режим без окна (headless). Команды с телефона проходят тот же путь, что и щелчок в окне консоли, поэтому оба устройства всегда показывают одно и то же состояние.

### Токен ведущего

Панель защищена `gm_token` в `config.toml`, который отделён от ключа доступа.

- Токен создаётся и сохраняется при первом запуске, если в конфигурации его нет. Он имеет такой же вид, как ключ доступа (16 символов: строчные буквы и цифры).
- `gm_token = ""` отключает удалённый доступ, и панель открывается только на этом компьютере. Консоль показывает `Remote panel is off: it opens on this computer only` и кнопку **Create GM key** (создание ключа ведущего), которая создаёт токен, чтобы панель можно было открыть с телефона.

В блоке **GM panel link** (ссылка на панель ведущего) консоли показана ссылка без схемы, а токен обрезан до четырёх символов. До запуска сервера выводится `Start the server to get the link`. Щелчок по ссылке копирует полную ссылку. Текст предупреждения: `Do not share with players: this link controls the console`. Кнопка **Show QR** (показать QR-код) рисует QR-код ссылки (по умолчанию он скрыт, потому что экран может быть виден игрокам, а кнопка неактивна, пока сервер остановлен). **Hide QR** (скрыть QR-код) убирает его. **New key** (новый ключ) сначала запрашивает подтверждение: `The current link stops working at once and every phone using it is disconnected. Players' links are not affected.` **Replace key** (заменить ключ) выдаёт новый токен и сохраняет его. Старая ссылка и её телефонные сессии перестают работать сразу. **Cancel** (отмена) сохраняет текущий ключ.

Ссылка имеет такой вид (`https://`, если HTTPS включён):

```text
http://<advertised-address>:<port>/control?g=<gm-token>
```

### Кто может открыть панель

| Запрос | Нужен токен | Результат |
| --- | --- | --- |
| С этого компьютера, без прокси, с петлевым `Host` | Нет | Разрешено. Страница отправляет заголовок `X-Bardwave-Control`. |
| Откуда угодно ещё или через прокси либо туннель | Да | Разрешено с токеном. Иначе `401`. |
| С ключом слушателя (игрока) | Не принимается | `401`. |
| `gm_token = ""`, откуда угодно, кроме этого компьютера | Невозможно | `401`. |

«Локальность» определяется по адресу сокета. `X-Forwarded-For` никогда не считается доверенным. Запрос считается удалённым, если он содержит заголовок обратного прокси (`X-Forwarded-*`, `Forwarded`, `X-Real-IP`, `Via`, `CF-Connecting-IP` и подобные) или если его `Host` не `localhost`, `127.0.0.1` или `[::1]`. Неверный, отсутствующий и отключённый токены получают один и тот же ответ `401`.

Токен можно передать как `Authorization: Bearer <token>` или как `?g=<token>`. Страница на телефоне переносит токен из адреса в `sessionStorage` (ключ `bardwave.gm.token`) и сразу убирает его из строки адреса. Перезагрузка в той же вкладке находит его снова; в новой вкладке понадобится полная ссылка заново. Оболочка страницы (`/control`, `/control.js`, `/control.css`) отдаётся всем, потому что не содержит секрета, поэтому перезагрузка без токена всё равно откроет её, а затем попросит открыть ссылку из консоли.

### Что работает с телефона

С токеном страница на телефоне предлагает элементы управления консоли:

- **Master volume** (общая громкость), **Duck** (приглушение; во время приглушения показывает `Ducked` и пометку `Ducking: <buses>`) и **Stop all** (остановить всё);
- **Scenes** (панель сцен) и **Stop scene** (остановить сцену);
- **Stingers** (стингеры);
- **Music** (музыка): плейлисты, **Prev** (предыдущий), **Play** (воспроизвести; во время воспроизведения показывает `Pause`), **Next** (следующий), **Stop**, **Shuffle** (случайный порядок), **Repeat** (повтор; `Repeat: off`, `all` или `one`), полоса перемотки трека и строка с текущим треком;
- **Mixer** (микшер): шины **Music** (музыка), **Ambience** (атмосфера) и **Effects** (эффекты);
- **Sounds** (звуки): для каждого звука кнопка **Play** (во время воспроизведения становится **Stop**), переключатель **Loop** (зацикливание) и ползунок громкости.

Строка состояния показывает `Connected`, `Connecting…` или `Offline, retrying…`. Страница переподключается сама с задержкой от 0.5 s, растущей до 10 s. Подключено может быть несколько устройств, и каждое видит все изменения. Если токен заменён, страница выводит `The game master link was replaced. Open the new link from the server panel.` и перестаёт работать. Другие сообщения: `Access denied. Open the game master link from the console again.` и `Open the link from the console` (без токена). Панель скрывает разделы, в которых нечего показывать (нет сцен, нет стингеров).

### Почему ключ игрока не даёт управления

Ключ доступа проверяется только на `/ws/audio` и `/api/status`. Маршруты панели (`/api/control/*`, `/ws/control`) никогда его не принимают ни в заголовке, ни в `?k=`, ни в `?g=`, а токен ведущего тоже не является ключом игрока. Игрок, у которого есть ссылка для слушателя, может слушать поток, но не может нажать ни одного элемента управления. Управлять могут только те, у кого есть токен ведущего, или тот, кто сидит за этим компьютером.

### Ограничения частоты запросов

- Каждый адрес клиента получает 10 неудачных попыток за 60 s (подсеть IPv6 `/64` считается одним клиентом). После этого сервер отвечает `429` с `Retry-After`, и даже верный токен отклоняется, пока окно не истечёт. Страница на телефоне тогда показывает `Too many attempts. Wait <n> s.` Запросы с этого компьютера без прокси не ограничиваются.
- Запросы, переданные через прокси на этом компьютере, используют один общий счётчик, который допускает 60 неудач в минуту. Злонамеренный клиент за тем же прокси всё равно может задерживать остальных. Выйти из этой ситуации можно, заменив токен ведущего или работая с панелью локально.
- `/ws/control` принимает не более 16 клиентов одновременно (следующий получает `503`), сообщения размером 4096 байт и 100 команд в секунду на клиента (лишние команды отбрасываются с сообщением `too many commands, slow down`). Клиент, молчащий 75 s, закрывается (сервер отправляет ping каждые 25 s).
- Локальный WebSocket с `Origin`, который не совпадает с хостом самой страницы, отклоняется (`403`), а локальное действие REST без заголовка `X-Bardwave-Control` тоже отклоняется (`403`), поэтому веб-страница с другого сайта не может управлять панелью из браузера ведущего.

> **Предупреждение:** По обычному HTTP токен ведущего передаётся по сети открытым текстом. Включите [HTTPS (защищённое соединение)](./https.md), прежде чем пользоваться панелью с телефона через интернет.

> **Предупреждение:** Обычный TCP-туннель (`ssh -R`, bore, frp и подобные) или прокси, который переписывает `Host` на `127.0.0.1`, выглядит как локальный доступ. Используйте такие туннели, только если задан `gm_token`.

<a id="headless-control-page"></a>

## Страница /control без окна

С флагом `--server-only` приложение запускается в режиме без окна (headless). Оно загружает библиотеку, сохранённую в `config.toml`, само запускает сервер для слушателей и работает до нажатия Ctrl+C. Страница управления в этом случае — единственный интерфейс управления. Горячие клавиши и таймеры сессии в этом режиме не работают, а библиотека, изменённая в консоли, требует перезапуска сервера, чтобы изменения вступили в силу.

```bash
soundshared --server-only
soundshared --server-only --profile <name>
```

`soundshared` — имя файла, который создаёт `cargo build`. Пакет `.deb` для Linux устанавливает его как `bardwave`. README использует `Bardwave.exe` для релиза под Windows (не проверено). `--profile <name>` (или `--profile=<name>`) выбирает профиль кампании с собственными `config.toml` и библиотекой в `profiles/<name>/` в каталоге данных.

В журнале показаны адреса. Сам токен в журнал никогда не записывается:

```text
Listener server available at http://<advertised-address>:<port>/?k=<access-key>
Control page (this PC only): http://127.0.0.1:<port>/control
Remote control: http://<advertised-address>:<port>/control?g=<gm_token from config.toml>
```

Строка `Remote control` появляется, только если задан токен ведущего. Схема — `https`, если HTTPS включён. Когда роутер выделяет проброс, в журнал добавляется строка `Router forwards ... internet URL ...`.

`GET /control` отдаёт страницу всем, потому что страница не содержит секрета. Маршруты данных требуют токен или локальный запрос. Локальный запрос без токена также должен отправлять заголовок `X-Bardwave-Control` (любое значение) при каждом вызове, включая `GET`; запрос с токеном такого заголовка не требует.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/control/state`, `GET /api/control/scenes` | Состояние панели и сцены. |
| `POST /api/control/play`, `stop` (`?id=`), `stop_all` (`?fade_ms=`, необязательный), `volume` (`?id=&value=`), `loop` (`?id=&on=`), `master` (`?value=`), `stinger` (`?id=`), `duck` (`?mode=` или `?on=`), `bus` (`?bus=music\|ambience\|sfx&value=`) | Команды звуков и микшера. |
| `POST /api/control/scene/activate` (`?id=`), `scene/stop` | Сцены. |
| `POST /api/control/playlist/<verb>` | Музыка. `<verb>` — это `start`, `stop`, `pause`, `resume`, `toggle`, `next`, `prev`, `seek`, `shuffle` или `repeat`. |
| `GET /ws/control` | Текущее состояние в реальном времени. Команды отправляются кадрами JSON с полем `cmd`, например `play` или `volume`. |

<a id="https"></a>

## HTTPS

С `tls = true` тот же порт отдаёт HTTPS и `wss://` вместо обычного HTTP, поэтому ключ доступа и токен ведущего шифруются при передаче. Без `tls_cert` и `tls_key` создаётся самоподписанный сертификат, а сертификат, который нельзя прочитать, приводит к ошибке запуска с `Error` вместо отката на HTTP. Настройка находится в разделе **Secure connection (HTTPS)** (защищённое соединение) панели, вступает в силу при следующем **Start Server**, а [HTTPS (защищённое соединение)](./https.md) описывает настройку сертификата и предупреждение браузера.

<a id="configuration-reference"></a>

## Справочник по конфигурации

Все параметры находятся в таблице `[server]` файла `config.toml`.

| Параметр | Тип | По умолчанию | Значение |
| --- | --- | --- | --- |
| `port` | целое число | `8080` | Порт прослушивания, от `1` до `65535`. |
| `host` | строка | `"0.0.0.0"` | Адрес привязки, IP-адрес. Значение, которое не является IP-адресом, откатывается к `0.0.0.0`. |
| `upnp` | логическое значение | `true` | Запрашивать у роутера проброс порта. |
| `access_token` | строка | создаётся при первом запуске | Ключ доступа. `""` открывает поток всем, кто может достучаться до порта. |
| `gm_token` | строка | создаётся при первом запуске | Токен панели ведущего. `""` разрешает доступ только с этого компьютера. |
| `tls` | логическое значение | `false` | Отдавать HTTPS и `wss://` через тот же порт. |
| `tls_cert` | строка | не задано | Путь к цепочке сертификатов PEM. Требует `tls_key`. |
| `tls_key` | строка | не задано | Путь к закрытому ключу PEM для `tls_cert`. |

```toml
[server]
port = 8080
host = "0.0.0.0"
upnp = true
access_token = "k3x9q2w7e1r4t6y0"
gm_token = "p8m2n5b1v7c3x9z4"
tls = false
```

С собственным сертификатом:

```toml
[server]
port = 8443
host = "0.0.0.0"
upnp = true
tls = true
tls_cert = "/etc/ssl/bardwave/fullchain.pem"
tls_key = "/etc/ssl/bardwave/privkey.pem"
```

Приложение читает `config.toml` при запуске, поэтому ручная правка любого параметра требует перезапуска. После этого `port` и `host` можно менять на панели, пока сервер остановлен (значения сохраняются); новые значения применяются при следующем **Start Server**, а `tls`, `tls_cert` и `tls_key` читаются при каждом запуске из настроек, которые хранит запущенное приложение. `upnp` читается только при запуске.

Конфигурация хранится в каталоге данных. Если рядом с исполняемым файлом уже лежит `config.toml` (в Windows — только если эта папка доступна для записи), либо там есть файл `portable.flag`, либо папка программы доступна для записи и не находится внутри macOS `.app`, используется именно эта папка. Иначе используется `~/Library/Application Support/Bardwave` в macOS, `%APPDATA%\Bardwave` в Windows и `$XDG_DATA_HOME/bardwave` или `~/.local/share/bardwave` в Linux. Именованный профиль хранит свой `config.toml` в `profiles/<name>/` внутри этого каталога.

<a id="symptoms-and-fixes"></a>

## Симптомы и способы устранения

| Симптом | Вероятная причина | Что делать |
| --- | --- | --- |
| `Access Denied` на странице слушателя | Старый или отсутствующий ключ в ссылке. | Скопируйте текущую ссылку через **Copy Link**. |
| Listen URL показывает `127.0.0.1` | Не найден адрес локальной сети, либо адрес привязки — петлевой. | Остановите сервер, задайте для **Bind Address** значение `0.0.0.0` или IP-адрес в локальной сети, затем запустите его снова. |
| Игроки из локальной сети не могут подключиться | Брандмауэр. | В Windows разрешите Bardwave (в том числе для общедоступных сетей) или запустите от имени администратора. В других системах откройте порт в брандмауэре самостоятельно (не проверено). |
| `VPN active (...)` | Маршрут по умолчанию проходит через VPN. | Выключите VPN для игроков из интернета. |
| `Internet: no UPnP router` | На роутере нет UPnP. | Включите UPnP или пробросьте порт вручную (не проверено). |
| `Internet: blocked by a second NAT (...)` | CGNAT или дополнительный модем. | Попросите у провайдера публичный IP-адрес. |
| `Remote panel is off...` | `gm_token = ""`. | Нажмите **Create GM key**. |
| `401` или `Access denied` на панели телефона | Токен ведущего отсутствует или неверен. | Снова откройте ссылку на панель ведущего из консоли. |
| `429` или `Too many attempts` на панели телефона | Слишком много неудачных попыток. | Подождите, пока не истечёт время `Retry-After`. |
| `The game master link was replaced` | Нажали **Replace key**. | Откройте новую ссылку ведущего из консоли. |
| Подсказка `Weak network: ...` | Потери или джиттер на соединении слушателя. | Подойдите ближе к роутеру или смените подключение. |
| Запрет засыпания экрана показывает `N/A (needs https)` | Страница по обычному `http://`. | Включите [HTTPS (защищённое соединение)](./https.md). |

<a id="not-verified"></a>

## Не проверено

Эти пункты взяты из кода и тестов, но не проверены на реальном оборудовании или в реальных сетях:

- Правило брандмауэра Windows на реальном компьютере и то, как поступают другие системы со своими брандмауэрами.
- UPnP на реальных роутерах, включая случай второго NAT и роутеры, которые принимают только постоянные пробросы.
- Страница слушателя в iOS Safari и Android Chrome: запрет засыпания экрана, элементы управления на экране блокировки, установка на домашний экран и внешний вид страницы в локальной сети без интернета.
- Сканирование QR-кода камерой телефона.
- Имя исполняемого файла Windows в релизной сборке.
